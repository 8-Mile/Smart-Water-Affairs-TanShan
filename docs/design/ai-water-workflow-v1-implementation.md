# 唐港智慧水务 · AI自然语言自动办事 V1（本地规则工作流）

## 本期目标与入口

- 操作入口：系统顶部 **问 AI**（沿用原本AI抽屉，无第二套聊天窗口）
- AI操作输入示例：
  1. `分析未来80毫米降雨并比较雨前调蓄方案`
  2. `比较雨水、中水、自来水的供水经济方案`
  3. `比较多水源方案，中水水质不达标怎么办`
  4. `分析多水源供水能力不足方案`
  5. `查询当前无人值守待处理事件`
- 输入后点击「解析指令」：先确定性解析，再执行具体业务工具，再返回可解释的计算结果；
- 分析结果可一键「打开完整业务计算页面」，同时带入降雨量或供水情景；
- 如当前岗位具有 `water:proposal` 权限且结果满足供水约束，点击「确认保存待审核草稿」后写入对应**原水资源业务页面**的草稿列表，不另建第三套数据。

## 业务逻辑

### 场景A：雨前调蓄

用户输入未来80mm降雨，工具解析出明确的 `rainMm=80`（其余输入采用固定MOCK配置），调用此前完成的 `evaluateDispatch()`，实时比较现状、雨前腾库、处理回用三种方案。

展示来水量、三方案预计溢流、风险和增量费用（可能为负，表示在假设价格下节约）；如本次方案仍可能溢流，明确提示没有消除风险。

如选择保存，调用共享 `saveDispatchDraft()`，写入原 `tanggang-water-dispatch-drafts-v1`；跳转 `/water/dispatch?rainMm=80&source=ai` 后加载该参数及草稿。对于输入多个雨量、非法数值，明确拒绝而非猜测。

### 场景B：多水源经济优化

解析通用三水源、水质受限、能力不足三种情景，再调用此前完成的 `evaluateMultiSource()`，返回分用途需求、雨水/中水/自来水分配、缺口和可比较的假设成本差。

如果中水不满足水质用途，则禁用相关路径；如果供水能力不足，禁止保存为完整供水方案，不输出没有基准的“节约”金额。

仅在授权与业务可行性均满足时保存 `tanggang-multisource-drafts-v1`，跳转 `/water/multi-source?scenario=...&source=ai` 保留相同场景和草稿。草稿只能由人员核查，无法控制泵阀。

### 场景C：查询集中值守事件

调用现有 `useUnattendedStore()` 的事件列表，返回已有事件ID、状态和标题；没有事件时明确告知“当前本地DEMO无未关闭事件，不代表全港正常”。提供跳转原集中值守中心按钮，不生成新事件。

## 工作流与安全边界

- **输入**：中文业务请求 → 规则解析，当前未接入实际大模型API。文案“AI自然语言”体现操作入口，不宣称LLM已自主推理。
- **执行**：直接调用已有且有单元测试的水量守恒、供需匹配及值守事件接口，不返回写死的演示答案。
- **可解释**：明确参数、方案比较、约束、风险及模拟数据来源；无真实气象、PLC、水质或计费数据。
- **权限**：只读查询需 `ai:ask`；写草稿需增加 `water:proposal`，统一按角色矩阵校验。
- **人工确认**：解析与计算不写业务草稿；用户明确点击保存后才提交。禁止未满足需求的供水方案作为完整草稿保存。
- **无生产控制**：AI解析器对“启动泵、下发控制、切换阀门”等请求返回不支持；没有任何真实设备写入。
- **日志**：沿用现有AI任务记录，展示已执行的工具与输入/输出摘要，不声称是真正的多个自治智能体协作。
- **草稿存储**：目前仍为本地浏览器的持久化演示记录；正式工程需服务端、审批链、审计和事务控制。
- **后续能力**：多任务规划、用户确认的常用流程模板、岗位偏好学习、跨页面组件编辑、真实语音与知识库检索尚未作为本次已完成能力。

## 手工体验

1. 打开 `http://localhost:5173/overview`；
2. 右上角点击「问 AI」；
3. 点击「80mm雨前调蓄」快捷提示，再点击「解析指令」；
4. 查看结构化计算与来源说明；可选择「确认保存待审核草稿」；
5. 点击「打开完整业务计算页面」，核对降雨量与草稿；
6. 回到AI助手，尝试「三水源优化」和「值守事件查询」；
7. 尝试输入“自动启动水泵并比较调蓄方案”，验证系统拒绝控制动作；
8. 切换为运维人员，验证可分析但不能写水资源草稿。
