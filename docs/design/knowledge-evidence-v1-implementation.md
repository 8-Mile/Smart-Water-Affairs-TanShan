# 唐山港智慧水务 · 第七个亮点：专业知识库与可追溯诊断 V1

## 1. 入口及演示方式

**本机统一使用端口 5174。** 不再改回 5173。

- 直接页面：`http://localhost:5174/decision/knowledge`
- 菜单：智能决策 → **证据知识与诊断**
- 从「健康与能效 → 设备健康诊断」点击「查看证据知识与诊断」，传入设备资产ID。
- 从「智能运行 → 跨系统关联处置」点击「查看相关资料与原文」，传入选中设备ID和问题；对独立MOCK故障预览不传入当前平台中不存在的告警ID。
- 从现有AI「问 AI」输入 `查找P-002振动异常的诊断依据`，系统按规则提取P-002和“振动异常”，执行知识检索并显示带原始ID、版本、章节的来源证据；跳转同一知识工作台，不创建另一套聊天系统。

**体验正反场景：**

1. 默认P-002振动查询：3份可引用的DEMO已审核摘录（使用说明、巡检标准、维修案例），另有未审核图纸被排除；原巡检/维修/已验收工单作为额外业务记录。
2. 将主题改为「出口压力偏低」：由于目前相关档案摘录不支持该主题，不引用振动文档推断压力异常，显示“依据不足”。
3. 从跨系统MOCK故障预览选择SP-004射雾器：该设备缺可适用的文档；显示缺口，不把P-002泵档案视为SP-004管网拓扑或共因证据。
4. 导入新的P-002本地文本：在「档案管理」先按设备过滤，再导入 .txt/.md/.csv/.json；导入默认未经审核，不能作为引用。管理者可填写实际版号、可定位章节、适用范围/限制与审核意见，完成**DEMO内摘录审核**后才纳入同设备同主题的可引用结果。
5. 只读用户可检索和阅读，不可保存核验草稿；值班/运维等授权岗位显式保存待审核草稿，管理者/管理员填审阅意见后可以执行DEMO审核。

## 3. 检索技术与业务逻辑

本期**不是云端知识库、向量RAG或大语言模型自主推理**，而是透明、可测试的本地规则检索：

1. 从自然语言或页面参数获取assetId、异常主题，可选alarmId；未提供具体设备时不猜测。
2. 识别有限专业主题：振动/机械、轴承温度、电流、压力、流量、泄漏/密封及综合资料浏览。
3. 只在当前设备 `DocumentRef.assetIds` 匹配的文件中查找，不跨工艺搜索与当前设备无关的说明书。
4. 必须同时满足：`reviewed=true`、未删除、`unavailable=false`、有可读取 `contentExcerpt`、有版号 `version`、有原文件章节/条款 `lineOrSection`、且摘录包含该问题类别对应术语。
5. 从真实存在的 `contentExcerpt` 截取前后可读的原始文本并生成可点击引用 `[文档ID · 版本 · 章节]`；不根据标题/文件名猜测正文。
6. 再读取同设备的业务事件、维修/巡检记录及已验收工单作为背景，保留它们各自的源ID、日期和跳转路径，不推断因果。
7. 只生成保守的人工核查建议；缺少同设备可引用的文档时，系统显式降级，禁止输出“确认根因”“寿命预测”或“直接停机”结论。

**检索结果的“参考可用”只表示通过本地证据筛选，不代表该文档或建议完成真实厂家/现场工程质量审核。**

## 4. 文档导入与审核边界

- 原文件导入能力只接受用户主动选择的 `.json,.txt,.md,.csv`，不会扫描Mac本地目录。
- 单文件超过256KB时，系统只保留元数据，不读取其内容，因此也不能进入审核/诊断引用。
- 对可读取的文本文件，本期只保存前2000字符 `contentExcerpt`，没有完整原文件存储及全文索引；在界面中明确称“档案摘录”。
- 用户导入的资料默认 `reviewed=false`。管理者或管理员可对**用户主动导入且有摘录**的文档记录真实版号、原文件章节和至少8字的适用性审核意见；改为 `reviewed=true`，记录DEMO审核角色/时间/意见以及原审计事件。
- 不允许用这个演示审核功能批准示例中的未审核DEMO工程图纸或无文本文件；审核不能证明实际图纸真实和工程可施工。
- 若资料需要修订，必须作为新版本重新导入；避免静默修改已经用于核验的文档。

## 5. 报告草稿与证据防失效

- 业务记录存储于 `tanggang-knowledge-diagnosis-v1`（本地localStorage），状态：`pending_review` → `reviewed_demo`。
- 操作员在看过查询结果后明确点击「人工确认保存核验草稿」，才将设备/场景/问题、可用文档ID/版本/章节、摘录内容变化令牌及历史业务记录引用保存。
- 管理者审核时重新读取当前 `store.documents`，检查被引用文档仍存在、审核标记有效、章节和版号一致、摘录内容未变化，以及**仍绑定原设备、来源类型未发生改变**；任一项失效就阻断旧草稿审核，要求重新检索和生成。
- **新增持续有效性检查**：审核完成的历史记录也不是永久可信。在查看时重新比对当前文档ID、版号、章节、当前设备绑定、摘录变化令牌和来源。若原文后续被删除、撤审、换版、改内容或解绑设备，旧记录标为「原引用失效 · 需重检」，直接显示失效原因，同时保留原始审核人和审阅日志；不静默更新旧引用。
- 已有草稿若本来就没有任何可引用原文，统一显示「仅缺口报告」，无论是否完成本地DEMO审核均不标「证据有效」。
- 摘录变更令牌是简单的客户端内容变化检查，**不是加密签名或不可抵赖审计**。
- 允许无文档的“证据不足/待补资料”草稿存档，不能将它表示为完成诊断。
- 不创建正式工单、不发出PLC控制、不关闭告警、不在后台执行任何调度。

## 6. 权限与可追溯性

- `process:read`：查看检索页面和已有文档；包括只读用户。
- `knowledge:save`：admin、manager、duty、engineer 保存DEMO待审核知识核验草稿。
- `knowledge:review`：admin、manager 复核报告草稿。
- `document:review`：admin、manager 对适用的**用户导入文本摘录**记录版号、章节和本地DEMO审核意见。
- `document:attach`：沿用原权限（admin、engineer），用于主动导入/移除文件引用。
- `ai:ask`：已有AI助手查看知识来源；不具备该权限的角色仍能从菜单浏览知识。

## 8. 工程落地前的必需资料与下一步

当前只有P-002的演示文档和一些模拟维修数据，不能宣称已覆盖六套工艺。进入真实试点需要：

- 合法可使用的设备厂家说明书及其对应设备型号/序列号，设备实际台账与版本管理；
- P&ID、水力设备与管网连接、真实测点表和维护履历；
- PDF/DOCX/扫描图纸提取与复核、分段索引、双向引用、权限与数据脱敏；
- 具名人工审签、服务端版本控制、防篡改审计；
- 将设备/事件/工单/知识摘录关联关系固化为可验证、受控的诊断规则；
- 由现场专业人员验证检查建议，记录采纳/误判/恢复结果，再考虑可审核的反馈学习。

本期仅完成**可解释、可追溯的检索与诊断依据工作流**，不声称大型语言模型“自学习”或生产设备自主诊断已经投入运行。

## 9. 本次继续开发的验收记录（2026-11-16）

本轮并未重复新增知识库入口，因为V1基础实现已存在；实际补齐了“**证据生命周期失效**”这条工程闭环：查看历史草稿不等于原资料永远可用。

- `inspectKnowledgeCitations()` 是统一检查点，供保存后的历史查询和人工报告审批复用；只作客户端摘录完整性对比，不代替签章或服务器不可篡改审计。
- 主题匹配新增 `K25` 反例校验：仅出现「轴承」「电机」「出水」这类泛词不代表文档涉及振动、电流或供压异常；专科证据必须出现更明确的专业术语。该规则仅减少误匹配，不等于正式语义检索。
- 历史草稿引用变化后不会删除审查轨迹；新建议必须重新查询同设备原始档案并形成新草稿。
- 演示删除档案引用必须由具有 `document:attach` 权限的角色执行（engineer/admin），与审核权限 `knowledge:review` 分离；测试不能以管理者身份绕过原有授权。
- 运行在 `http://localhost:5174/decision/knowledge`，5174端口为用户指定，不应自动切换回5173。
