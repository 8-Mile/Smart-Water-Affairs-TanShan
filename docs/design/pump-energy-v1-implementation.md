## 为什么不能直接用已有遥测计算实际效率

当前中压供水设备台账是 MOCK：
- P-001：75kW / 320m³/h / 72m，运行。
- P-002：75kW / 330m³/h / 74m，运行。
- P-004：75kW / 315m³/h / 72m，停机热备。
- 已有的压力、流量、电流测点为模拟时序。
- **缺少经确认的输入电功率（kW）、电能（kWh）、总扬程、设备运行点的厂家Q-H曲线、效率曲线和共母管/阀门拓扑**。
- 电机额定功率不能当作运行有功功率；电流也不能在缺电压、功率因数、实际电机效率等数据时直接换算出可靠运行电耗。
- 泵出口压力本身不能直接代表系统总扬程；还需考虑吸入口、位差、流速头和损失。

因此 V1 采取明确标记的 **单工况点假设 + 给定日供水量的定频泵运行时长计算**。没有做虚假的连续Q-H/η-Q曲线拟合，也没有计算跨时段水力最优调度。

## 模型输入和计算

输入：
- 日任务供水量 `V (m³)`；
- 峰时供水能力需求 `Q_peak (m³/h)`；
- 系统要求的最小总扬程 `H_required (m)`；
- 单台最大每日运行小时数 `T_max (h)`；
- 假设综合电价 `C_e (元/kWh)`；
- 备用约束（需要保留多少台已确认可用的备用泵）；
- 每台泵的运行状态、备用投运条件、模拟运行点 `Q_i,H_i,P_e,i`、模拟铭牌参数。

公式：
- 水力功率：`P_h(kW) = 9.81 × Q(m³/h) × H(m) / 3600`（水密度1000kg/m³的近似值）。
- 综合效率：`η_wire-to-water = P_h / P_e`；所有数值来自假设运行点，**不能称为实测泵效率**。
- 运行点单位水量电耗：`e_i = P_e,i / Q_i`，单位kWh/m³。
- 并联运行点组合总出流：`Q_combo = ΣQ_i`，总功率：`P_combo = ΣP_e,i`（**假设**各泵在设定工况点共同运行，这本身不是经过水力校核的结论）。
- 完成供水任务所需共同运行小时：`T = V/Q_combo`。
- 预测任务耗电：`E = T × P_combo`，预测运行电费：`E × C_e`。
- 条件模拟组合节电：`E_current_combination − E_best_feasible`，仅当现行组合在本次条件下可行时提供。
- 所有候选组合以相同任务量和相同输入条件比较，不能将两种不同供水量混为节能。

约束：
1. 故障/未知状态设备禁止参与推荐；
2. 停机备用泵未经人工假设确认投运条件，不进入候选；
3. 模拟工况扬程不能小于系统所需总扬程；
4. 组合流量需覆盖峰时能力需求；
5. 共同运行小时不能超出单泵允许时长；
6. 用户可附加至少1台已确认可用备用泵约束；
7. 不允许水力功率超过电功率（效率>100%），不允许假设运行点超出演示铭牌Q/H点或电功率超出铭牌；
8. 无可行组合时明确拒绝推荐，现行组合不可比时不输出假设节约金额。

**注意：** 这些约束只能排除一部分明显不合理的模拟方案，不能替代Q-H交点、最小流量、汽蚀余量、系统特性曲线、能耗分时电价、联锁、调度许可或水力瞬变校验。

## 默认演示值（全部 MOCK）

- 同一日任务：5500m³，峰时需求300m³/h，最小总扬程70m，单泵运行上限18h；
- 假设电价：0.85元/kWh；
- P-001假设运行点：320m³/h、72m、输入电功率75kW；
- P-002假设运行点：330m³/h、74m、输入电功率75kW；
- P-004假设运行点：315m³/h、72m、输入电功率71.5kW，但**未确认备泵可投运**；
- 当前组合模拟：P-001 + P-002，150kW，650m³/h，完成任务需约8.46h，约1269.23kWh；
- 条件模拟优选：P-002单泵，75kW，330m³/h，完成同一任务需约16.67h，约1250kWh；
- 假设节电约19.23kWh、假设电费差约16.35元，约1.52%。**绝不用于宣称现场实际节电收益**。

提示：默认两个输入功率数值恰与75kW铭牌功率一致，仅属于人为设定的独立MOCK工况点，绝非据铭牌推算的电表读数。可在专业参数区修改这些假设值并重新计算。

## 页面与流程

1. 打开「智能决策 → 健康与能效」，点击「泵组能效匹配与运行优化」；
2. 默认查看日供水量、现行组合模拟电耗、条件优选的单位电耗和模拟节约；
3. 逐项对比全部7种组合；条件不足的候选仍显示但明确给出阻断原因；
4. 选择“正常供水 / 高峰双泵需求 / 模拟P-002故障 / 假设备用泵已核验”四个情景，查看同一模型动态重算；
5. 点击“调整计算条件”，可修改供水目标、峰值、总扬程、运行上限、电价、备用台数，以及各泵假设流量、扬程、有功功率；
6. 参数更改后必须重新计算才生效，未同步修改时禁用保存；物理输入明显自相矛盾时拒绝重算并保留上次有效结果；
7. 有授权岗位点击“保存待工程复核建议草稿”，仅写入 `tanggang-pump-energy-drafts-v1` 本地浏览器存储；记录场景、人员、参数、推荐组合和假设节约；
8. 保存不会创建工单、不会更改设备状态、不会自动调度或操作现场PLC。

## 权限与业务边界

- `energy:proposal`：管理员、管理者、值班运行员、运维工程师可保存模拟计算草稿；只读访客仅能查看；
- 草稿状态固定 `draft`，没有现场工况验收、正式审批或执行状态；
- 更改MOCK模拟故障/备用开关不会修改原设备台账和实时状态；
- 本地草稿最多30条，并按当前模拟场景筛选；未接服务端数据库。

## 下一阶段进入真实工程试点的前提

须取得：
- 与P-001/P-002/P-004实际型号一致的厂家或试验Q-H、P-Q、效率-流量曲线，及允许的最小/最大持续运行流量；
- 泵吸/出水压力与液位、流量、实时有功功率、累积电能，核对时钟、单位、传感器数据质量；
- 泵站管网拓扑、母管汇流、阀门状态、吸入条件、汽蚀余量NPSH、实际控制模式（定频/变频）及联锁策略；
- 每日与峰小时供水负荷曲线、水池容积与允许调蓄、供水可靠性/备用要求；
- 电费合同、分时电价、运行维护与启停代价；
- 运行班组与审批权限、工单执行和恢复验证标准。

只有完成上述校核后，才可以把单点模拟扩展为**实际工况曲线匹配、跨时段优化和可验证的节电成果评估**。

原健康趋势与维修工单、智能值守、雨前调蓄、水源优化、AI自动办事全部保留。
