# 唐港智慧水务 V3.2：逐池工程台账—V-H曲线—测点—污染水业务链

2026-11-17。项目在原5174系统上更新，未另建DEMO。本文是**软件开发与工程证据验收底稿**，不等同于竣工、仪表标定、工程签认或真实自动控制。

## 一、工程问题与本轮定位

港口需要知道污染径流能否收得住、污水能否处理、合格出水能否送到真实码头冲洗终端。此前的污染水业务模型是“一个假设污染池加一个假设清水池”。它不能代表现场所有池体彼此相通。

现有前期资料对总容量存在不同口径，特别是70,638.9m³与60,739m³。未经批准图纸比对、逐池高程核查，不接受任一口径作为现场可用库容，也不能把多座生态池、初雨池、后雨池和清水池直接加总成可调蓄容量。六套工艺也并非同一物理地点。

**本轮目标**：把池号、用途、图纸版本、V-H曲线、液位测点、模型参数来源、人工审核和P0核查任务连成一条可操作、可追溯、但不冒充真实验收的资料链。

## 二、交付功能

### 1. 一池一号资料台账

每个池体分别记录：唯一编号、名称、类别（污染水收集/初雨/后雨/生态/处理清水/供水）、所属工艺、站点分区、图号、图纸版本、液位高程基准、最低/最高工作水位、V-H节点、可选假设起始液位、可选测点ID。用途与工艺关系受校验，不允许将后期雨水/生态池当作已达到水质要求的处理后清水池。

**为演示数据结构而内置的MOCK样本只有两座，均非港口实物：**
- MOCK-POOL-D，假设污染池：有效6200m³，模拟初始1800m³；
- MOCK-POOL-C，假设清水池：有效2200m³，模拟初始450m³。

这两个数值只是当前V3污水情景模型的原有参数，不是经过图纸确认的真实池体、真实水位或实测库容。用户新增的真实编号需要依据设计和现场资料，不自动产生真实池数。

### 2. V-H插值、可用容量计算和约束

已登记的曲线必须有3–30个节点，液位m严格递增、累积库容m³严格递增。只允许在曲线覆盖范围内进行分段线性插值，严禁外推，也阻断负数、NaN、无限值、重复节点和倒置工作水位。

插值公式：V(H) = Vi + (H-Hi) × (Vi+1 - Vi) / (Hi+1 - Hi)。

有效容量 = V(Hmax) - V(Hmin)；仅供情景使用的假设初始储量 = V(Hscenario) - V(Hmin)；假设剩余空间 = 有效容量 - 假设初始储量。

上述数值只在给定V-H的条件下成立。没有统一设计高程、真实最低运行水位与现场液位之前，**不能输出实际可用库存，也不能依据该模型自动腾库容**。

### 3. 逐池液位测点映射

测点必须为数值点、单位m、名称为液位/水位；所属资产必须是池/井/罐或对应液位设备，工艺与所登记的池体一致；一只测点不能被两座未归档的池重复绑定。任意失败均拒绝关联。

目前种子中的雨水集水池液位使用百分比%，不能直接转换为V-H曲线的米制高程。需要现场核查量程、起算点、基准标高和仪表标定，必要时复用或补装米制液位计。绑定本地MOCK测点也不代表真正的现场设备已验收。

### 4. 资料生命周期及角色

本地资料存在独立localStorage键：tanggang-v32-basin-registry-v1，不覆盖旧V3.1工程审查或业务记录。支持新增、修订版本、审核、退回、软归档和修改历史；权限复用engineering:submit与engineering:review。viewer只读，工程岗位不能代替管理者审核。

状态submitted、reviewed_demo、returned只表达**本地DEMO资料流程**。fieldVerified=false、controlReleased=false始终保持，任何人工模拟审核均不会将正式现场签认变成已通过。真正工程档案与多用户审批需要后续服务端方案和业主认可。

### 5. 现场核查CSV交付

可点击“导出逐池核查台账CSV”，导出用户登记、未归档的池体资料，包括图号、基准、曲线、角色、版本及“现场未验收”列。**MOCK示例不出现在正式资料导出中**。字符串导出防护Excel公式注入，文件可以交由水工/仪表人员填写、比对和核查。当前没有实现批量Excel导入，避免未经校验直接写入模型。

### 6. 污染水模型联动

入口： http://localhost:5174/water/port-chain?scenario=storm

业务链新增“从逐池V-H曲线加载单池MOCK参数”。可以分别选择一座污染水池或一座处理后清水池，将有效容量和假设起始储量加载为模型参数；不自动跨池合计，不改变原有默认情景，也不自行推导真实水路。

载入后必须显式点击“重算情景和风险”才能将模型运行结果作为新快照保存。MOCK分析记录保存basinSources中的池体ID、修订版、对应污染/清水池角色以及fieldVerified=false，以便回溯参数来源。原有入站管道、水质合格、冲洗终端连通三道闸门继续有效，不会因有库存就宣称可合法处理/回用或许可排放。

雨水收集、含矿污水处理、水池供水的原工艺页已新增“逐池V-H台账”下钻入口；SCADA和原业务逻辑均保留。

## 六、真正下一步要拿到的工程资料

1. 由设计/建设单位提供批准并版本唯一的逐池构筑物清单、竣工图、统一高程、水尺标定及有效V-H曲线。
2. 由排水/机电专业确认分区汇水、每池入水/出水、池间阀门、止回、泵站、排口、处理站的真实连接和水力高程关系。
3. 由自控/仪表提供PLC/SCADA点表，液位（m）与泵出口流量（m³/h）逐点绑定、时标、质量码、报警和FAT/SAT。
4. 由环保、生产核定处理站有效负荷、水质合格标准、清水池出水以及码头面冲洗真实需求，避免虚报连续回用和节水效益。
5. 在工程证据具备后，建立以池体ID和进出水计量为基础的分池逐时水量守恒、异常识别、人工工单与恢复复核，最后再研究合规的半自动优化。

**结论**：V3.2实现了“池体证据可登记、库容计算有依据、模型参数来源可追溯”的软件能力；不是“真实港口库容已经测定、池间管道已查明或调蓄已经自动投运”。
