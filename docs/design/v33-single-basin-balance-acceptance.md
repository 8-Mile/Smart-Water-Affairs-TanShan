开发日期：2026-11-17。直接修改原Smart-Water-Affairs-TanShan项目，保持本地5174服务与既有导航，不另建项目、不重做源码包。

## 一、目的与范围

业务目标是辅助回答：“某一座污染水池或清水池，同一时间窗内，池容变化和进出水累计量是否相符？不符时谁核查、核查什么、能否留下依据？”

本阶段不是全港自动调度，不是全港总库容计算，也不是据此直接推导泄漏、污染或仪表故障，更不对PLC下发控制动作。六套工艺分散布置；每池流量计、液位计及跨池连接需要现场核验。

## 二、入口与交互流程

- 原系统： http://localhost:5174/
- 第五个工程工作区： http://localhost:5174/engineering/registry?focus=balance
- 逐池资料： http://localhost:5174/engineering/registry?focus=basins
- 港口污染水业务链： http://localhost:5174/water/port-chain?scenario=storm
- 原工单中心： http://localhost:5174/operations/workorders

人工操作：选择一座非归档池 → 查看所属用途、资料版本及V-H来源 → 输入同一时间窗口的起止液位（m）及累计进/出水量（m³） → 计算残差 → 保存仅本地待核快照 → 人工受理异常 → （具备候选设备与唯一液位点绑定时）经人工确认后生成既有工单草稿 → 按现有工单中心处理、验收 → 用原核算后续时段的新快照验证 → 管理者进行DEMO复核闭环。

MOCK样本无真实设备归属，只可进行计算和人工受理，**不能**自动把MOCK异常挂到真实或无关联的资产。系统不在任何阶段创建自动生产报警，不把内部审核作为正式工程签认。

## 三、计算口径及规则

逐池V-H曲线仅在其覆盖的水位范围内执行分段线性插值，不外推。所有库容均从该池的最低工作液位扣除基线累积容积。

- 起始储量：V(H始) - V(Hmin)
- 结束储量：V(H末) - V(Hmin)
- 观测储量变化：结束储量 - 起始储量
- 计量净增量：同周期累计进水 - 同周期累计出水
- **水量守恒残差**：观测储量变化 - 计量净增量
- 预测期末储量：起始储量 + 计量净增量
- **仅供演示的提示容差**：max(20m³, 5% ×（累计进水 + 累计出水）)

残差绝对值大于演示容差、或者预测期末储量不在该池容量边界内时，提示“疑似偏差”；否则提示“未触发演示阈值”，**绝不表述为现场正常、计量准确、可用库容已审定**。

上述20m³和5%均为软件演示规则，没有设计/环评/水务监管或业主校准依据，**不能**作为港口项目真实报警阈值投运。真实实施应建立计量误差预算、仪表精度、时钟同步及采样周期、水体损失项与支路计量覆盖，分池分工况共同标定，阈值由设计/运行专业审批。

## 四、异常闭环边界

1. 无效时间、时间倒序、超过7天的核算周期、负累计量、超过池体工作液位、NaN/Infinity及池体修订版冲突均阻断计算。
2. 用户每次修改输入，先前计算结果立即失效；保存时仍会重新调用校核。
3. 人工受理仅由具备engineering:submit权限的角色执行，至少8字说明，保留历史记录；viewer只能计算预览。
4. 工单关联须使用**已登记的一对一候选液位测点所指向的同工艺资产**，再次核对测点单位和资产种类；不允许随意选择设备进行归责。人工确认后仅创建manual来源的原系统工单草稿，带本次核查ID，防重复创建。
5. 不代替工单派发和验收。DEMO闭环须关联工单已在原系统验收归档、原核算结束之后出现同池同版未触发演示阈值的新记录，并由管理者填写复核说明。
6. 所有核查快照仅存浏览器localStorage键 tanggang-v33-basin-balance-v1；不与SCADA历史库或工单正式服务端数据库声称同步。跨设备、跨人员同步另需后端工程化。

## 五、工程数据缺口（现场阶段）

- 池体清单、竣工图、统一高程基准、V-H曲线与最低工作液位。
- 一池一号资产及液位/水尺/流量计逐点映射，仪表精度、零点标定、单位、采样周期、质量码。
- 逐池进水、出水、溢流、旁路和池间联系及阀位，处理站和回用终端真实连接依据。
- 用水量/处理量/排放量的统计周期与环保合规要求，以及不计量损失和雨污分流边界。
- 异常阈值设计、岗位受理矩阵、现场工单归档和设备恢复核验规则。
