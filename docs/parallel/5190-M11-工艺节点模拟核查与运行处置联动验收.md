# 唐港5190 · M11 工艺节点模拟核查与运行处置联动

## 业务主线与边界

本轮继续原定七大菜单、六专业工艺及供水、主动监护、模拟研判和复盘的Mock产品设计，以完成可操作DEMO为优先。所有数据和节点状态仅为用户提供资料背景下的SIM示例，不作为现场采集、环保合格、泵阀控制、维修验收、正式告警或工单依据。采集硬件、协议与业主资料在完整DEMO验收之后按用户单独要求研究，不作为当前软件开发前置条件。

继续使用既有浅色磨砂卡片、Element Plus、字体和路由。三维场景、模型、CAD源数据、材质纹理以及TRAE的docs/migration不属于本次修改范围。

## 完成的操作闭环

1. 原六系统工艺节点Mock详情增加“SIM节点核查与后续处置”，已启动全局SIM情景时可对原有CAD设计设施填写8至600字的人工核查意见，留存当期模拟状态、来源设施和SIM运行UID。没有情景时引导到统一控制台。
2. 一个系统内多设施可以独立记录；同一轮同一设施重新提交可更新当前意见。跨路由跳转保留；重新运行或退出SIM，浏览器内存节点核查清空。此处不存真实设备巡检记录。
3. 节点可以跳到原主动智能监护、模拟处置研判及其供水或雨水分析页面。已有权限时另有“查看正式告警中心/维修工单”入口，绝不创建、关闭、筛选或预填不存在的生产事件。
4. 来源节点标识作为路由查询附带，目标页必须在当前浏览器Pinia状态中查找到来源系统、设施ID及完全一致的本轮UID后才展示节点意见和“返回原工艺节点”按钮。随便修改URL不能伪造已记录核查。
5. 同轮SIM上下文增加process_checks数组。后端限制系统为既有六个，设施ID符合CAD映射命名规则，严格限制数据模式为SIM、未验证、未创建正式告警和工单，且所有记录与当前情景和运行UID一致、不得重复；最多24项。
6. AI助手原“生成本轮SIM运行复盘报告”机制将同轮节点核查快照冻结在独立Mock报告中。复盘页面展示设计设施、模拟状态、人工备注与原设施入口，但仍不构成真实工单证据和现场操作履历。
7. 修复了参数422错误响应在Pydantic上下文包含ValueError对象时无法JSON序列化的问题，非法和跨轮次SIM记录可安全返回422，不写入正式业务表。

## 验收步骤

1. 打开中压泵设计设施，启动全局“中压泵异常”SIM情景，检查模拟状态和监护数值。
2. 填写人工模拟核查意见并保存；跳转主动监护，确认回显来源设施和相同意见，再返回工艺节点。
3. 点击“模拟处置研判”，确认入口保持相同模拟轮次和节点来源；可在原界面继续选择研究方案。
4. 打开AI智能助手，以“生成本轮SIM运行复盘报告”执行原人工确认流程；复盘应保留节点模拟核查记录与设备导航。
5. 再次运行不同情景，核实上一轮节点意见不会混入当前情景，旧来源URL不得冒充新轮次。
6. 验证正式告警/维修工单页面只读导航，不会通过SIM状态直接产生生产数据库记录。

## 其他限制

本轮不建设新的工单管理、监测规则编辑器或通用SCADA组态引擎；保留原成熟产品页面。后续仍然优先深化六系统的专业组态与业务流转，待完整Mock产品稳定后再统一讨论现场采集能力和硬件需求。
