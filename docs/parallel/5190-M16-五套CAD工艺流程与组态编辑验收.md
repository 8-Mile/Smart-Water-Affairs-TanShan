# M16｜五套非射雾子系统基于CAD资料重建工艺流程

## 本轮修复的实际问题

原有五套组态图只按CAD分区摆放设施，`defaultProcessDiagram()` 的连线数组为空，不能表达工艺。射雾除尘原有完整流程保留。

本轮把五套子系统改为：工艺来源/收集、核心过程、分支去向、辅助测点与控制，继续复用原5144可编辑组态的草稿、发布和历史机制。严禁把工艺逻辑推导冒充DWG经核验的管道几何。

## 工程证据

- `frontend/public/tanggang/cad/l1-v2_3/region-equipment-v2.3.json`：CAD设计设施名称、区域、建议测点
- `frontend/public/tanggang/cad/l1-v2_3/V2.3_区域水路关系.csv`：设计分区水路关系/条件路径
- `frontend/public/tanggang/cad/l1-v2_5/systems-v2.5.json`：六系统对CAD区域/设备/管线图层的映射
- `frontend/src/modules/tanggang/scene/config/pipeLayers.ts`：中压、雨水、污泥、中水、自来水和生活污水的CAD图层
- 第四分册、第五分册、设计方案归纳：用于工艺基本过程梳理，**不替代图纸管段端点核验**

**不具备的证据：** 本机工程仓库当前没有可直接核验的原始DWG/DXF连通实体；既有L1 V2.3是从CAD提取的设计映射，资料中已明确“图层存在 ≠ 连接/流向确认”。所以每条软件组态连线仍为 `verification=illustrative`，区域设计关系与物理管段方向不能混称。

## 五系统图上业务闭环

|系统|设计设施|软件流程节点（可含非设备参考标签）|主要关系|限制|
|---|---:|---|---|---|
|中压供水|7|取水参考→中压泵→出水计量→中压主管→水车、洗车和码头用水|中压管线图层 `$管综-中压除尘`；泵房对堆场与码头供水|水车/码头各具体支路标条件，未做端点/阀门/三通确认|
|含矿污水处理|16|北侧格栅/进水提升/二次提升 + 南侧前端/二次提升→高效净水器→清水池及回用分支；加药支路；污泥→污泥池→压滤|北池进入处理场；处理达标清水回补除尘水池/生态调蓄；污泥专业|南侧直接入处理场为设计备选；生态外送条件关系；泵、格栅的具体物理串接仍待核|
|雨水收集|10|堆场/码头排水→南北独立闸门→南北独立集水池→提升→含矿污水处理跨系统参考|地面排水和南北集水；码头经南侧|南北池不合并，南侧去处理路径条件；雷达液位计作为辅助测点，不串入水管|
|水池供水|11|市政中水、市政自来水、含矿处理清水、生态条件补水→进水阀→进水计量→除尘水池→射雾/中压泵组及计量|市政专业图层、清水池回用与泵房取水|两座除尘水池的单体几何/切换阀位未核，只绘一处CAD设施类别，不虚构为两处已核实对象|
|生活污水处理|3|生活污水收集→外接既有处理场 / 一体化处理设备（**两个备选路径**）；独立办公生活用水计量|生活污水专业图层|两个污水去向未核，不能串联；办公用水不可接入污水管路图|

**画线语义：** 蓝色代表水路工艺关系，灰色控制信号参考，棕色污泥支路，黄色加药支路；疏虚线表示条件/备选路径。所有线都属于设计工艺示意；不是实际管道拓扑。

## 前端与后端变更

- `frontend/src/modules/tanggang/business/processFlow.ts`：五系统按CAD编号布置各自的工艺节点、区域分段、连线与条件标识，要求原CAD设施无遗漏、无虚构。
- `frontend/src/modules/tanggang/business/fogDiagram.ts`：非射雾模板从“空连线分区图”升级为流程图；射雾原模板不改变。
- `frontend/src/modules/tanggang/business/PortFogDiagram.vue`：按工艺段分区，绘制介质不同的流程箭头/条件标签；提供阶段快速定位；编辑连接时可以选择水、污泥、加药、控制信号，设置设计/条件路径及连接说明。历史零连线版本显示新流程预览但不自动覆盖，人工进入编辑并发布。
- `frontend/src/modules/tanggang/business/PortProcessEffect.vue` + `PortProcessView.vue`：五套效果图也以相同CAD设计流程图为数据源，切换效果图不再出现孤立设施陈列；存在新版已发布组态时优先读取发布版本。射雾原效果分区保留。
- `frontend/src/api/tanggangProcessDiagrams.ts` + `backend/app/api/tanggang_process_diagram.py`：新增 `sludge`、`chemical` 介质，以及兼容旧记录的 `relation`、`label` 可选字段；后端仍强制 `verification=illustrative`、系统/设施编号白名单、乐观锁及权限校验。
- `frontend/src/modules/tanggang/business/__tests__/processDiagramSixSystems.test.ts`：CAD设施覆盖、流水分支、介质、条件流程、既有无连接版本识别、防跨系统绑定。
- 未修改其他业务页面或真实设备控制接口。

## 用户端操作

从 `http://localhost:5190/port/process/middle` 等六系统页面进入“组态图”：
1. 页面先显示完整流程初稿；根据阶段导航定位水源/处理/去向。
2. 点击设备显示右侧设计设施与演示数据。
3. 点击“编辑组态”可拖动、添加、绑定CAD设施与测点、编辑连线；对已发布无连线旧版会要求确认载入CAD流程底稿。
4. 保存草稿与发布分离；只有有发布权限的账号能够发布。未发布的改动不覆盖旧运行版本；历史可恢复为草稿。

## 尚须业主/图纸复核

1. 原始DWG转带图层DXF或导出水务专业PDF，逐段提取管线端点、阀门、三通和管径、材质/介质；
2. 北池、南池及堆场、码头的真实汇流方向、南侧二次提升的可用路径；
3. 污水站进出水、加药、污泥和清水回用的设备序列、药剂入药位置；
4. 两座除尘水池单体设备台账与市政中水/自来水接入条件、配水策略；
5. 生活污水接入既有处理场与一体化设施是否并存、各自去向。

达到以上校核，才能把“设计工艺逻辑图”升级成“经图纸核验的SCADA工程组态图”。
