# 唐港5190 M17 · 五套CAD工艺流程自动布线与双视图一致性验收

## 目的

承接提交 f593732 的五套工艺主流程与分支模型，修复连线从设备中心穿过、跨图元遮挡、设计效果图与组态图布局不一致，以及在六系统之间切换时旧系统已发布流程残留的问题。保持射雾器除尘原有布局和交互，保留草稿/发布/历史版本。

## 范围与结果

- 新增 `processFlowRouting.ts`：通过设备边缘连接点及正交候选线路，以碰撞优先惩罚选取示意路径，避让**非连接两端的CAD设计设施图元边框**。返回可复用的 SVG 路径、折点数组与沿路径定位的注释位置。
- `PortFogDiagram.vue` 使用共同的路由结果渲染非射雾组态，设备拖动后自动重新计算；射雾保留原算法。
- `PortProcessEffect.vue` 使用同一路由结果，保证效果图和组态图对于当前设计流程采用相同连接表达；共享的关系数据不等于CAD图元端点经验证。
- `PortProcessView.vue` 为效果视图按系统ID加稳定的重新挂载键；效果组件还检查发布数据的 `system_id`，防止路由切换时显示上一系统组态内容。
- 保留含矿污水处理清水/污泥/加药支路、雨水南北池、生活污水两条备选去向等业务关系。

## 证据约束

- 数据仍来自项目已建 V2.3 CAD 设施/区域/水路关系表与 V2.5 六系统映射。
- V2.8 CAD 端点核查台账存在 `unmatched_visible_endpoint`、`hidden_source_continuation` 等尚需进一步确认的端点状态，不能直接据此宣称所有真实管段闭合。
- 计算出的所有连线只是设计逻辑示意，不是DWG实际连线、真实泵阀控制逻辑或实测水力流向。
- 当前版本只做软件 Mock 演示，不写现场PLC，不自动覆盖用户已发布的历史组态。

## 自动化测试

- `processFlowRouting.test.ts`：对五套系统逐条验证连接由设施边缘出发，不穿过无关设备图元；另外覆盖无效端点、编辑后自动更新路径。
- 前端 `vitest run src/modules/tanggang/business/__tests__`：10个测试文件、60项通过。
- 浏览器隔离后端接口的六系统验证：效果图/组态图切换、工艺阶段定位、设备右侧详情、编辑发布共六套通过；**写入全部是浏览器内存Mock，不是对正式数据库发布**。
- 六系统浏览器无业务脚本异常；无GPU headless Chrome报WebGL初始化信息已与本模块错误区分。
- Vue TypeScript 编译校验单独执行。
