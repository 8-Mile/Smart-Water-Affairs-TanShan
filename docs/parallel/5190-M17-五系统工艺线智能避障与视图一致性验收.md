# M17｜五系统设计工艺连线避障与视图一致性

## 目标与边界

M16 已基于 CAD V2.3/V2.5 的设施和设计关系建立五套逻辑工艺组态，但旧版 `schematicRoute` 在复杂支路会以简单折线穿过其他图元。本轮仅处理示意图中的视觉布线，不改变水力关系，不新增 CAD 事实，不调整射雾系统，不向 PLC 写入。

## 本轮开发

- `processFlowRouting.ts`：根据设备矩形边缘自动生成正交连线，尝试多种绕行通道，优先选择不穿过无关设备、折点较少、长度适中的连线；连线标签定位使用路径沿线中点，而非图元中心中点。
- `PortFogDiagram.vue`：除射雾之外的五套组态显示使用新的路径与标签，拖动设备图元会依据当前节点坐标重新布线。射雾继续使用原有路线。
- `PortProcessEffect.vue`：效果图与组态图使用同一流程避障算法，切换不改变流程语义。
- `processFlowRouting.test.ts`：五系统所有设计连线的跨设备避让检查、缺失端点安全性及节点移动后重绘检查。

布线结果仍属于**设计流程示意**。CAD原始DWG尚未完成逐管段端点、阀门、三通与水力方向的人工校核，所有线保留 `verification=illustrative`。

## 验收情况

- M17路由专项测试 7/7 通过，五套子系统所有既定工艺连线均未穿过无关设计设备矩形（按 UI 预留边距判定）。
- Vue 类型检查通过。
- 现有六套浏览器 E2E 采用模拟接口验证图元、流程阶段与保存发布。射雾、中压供水在全量执行的前两项通过；含矿污水单独运行通过；雨水收集、水池供水、生活污水按独立批次通过。全量六套联合执行曾在含矿污水的发布状态等待上超时，后续独立复测已通过。原因更可能是本机并行 CPU 负载，但尚无性能剖析数据证明。
- 另有同一工作区的并行开发改动，本次不提交、不覆盖或重置其他模块。
