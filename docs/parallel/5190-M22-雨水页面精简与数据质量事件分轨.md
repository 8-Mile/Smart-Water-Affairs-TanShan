# 唐港 5190 · M22 雨水页面精简、操作栏布局修复与数据质量/事件分轨

## 目标

承接 M21 `9f3ba35`。本轮用户明确指出：

- “雨水调蓄的这个页面的说明那部分也要去除”；
- “右上角的按钮别遮盖了，要修复”；
- 继续下一步工作，但不能再增加要求手动调节的演练流程。

因此优先处理两张页面的真正布局问题，再推进 M22 数据契约与模拟/正式事件的严格隔离，保持原浅色设计体系和系统结构不变。

## 1. 页面精简

`PortRainRiskView.vue`：

- 移除主内容区重复的“水资源管理/雨水收集”面包屑、大标题、流程副标题。
- 移除独立的“工程边界”长段横幅。
- 移除“SIM/当前情景”的大块文字说明卡，改成紧凑的动态运行风险状态行。
- 移除风险核查卡中的长段流程引导文字和重复提示，改为同源的自动事件处理组件；雨水页面只显示源系统为 `rain` 的事件，不混入中压泵、供水和生活污水事件。
- 保留累计降雨、径流汇入量、预计溢流、调蓄容量和进度，以及“雨水收集工艺”的有效入口。
- 折叠的“处置建议与核查依据”属于操作所需详情，按用户主动点击后展示，不在页面首屏堆砌。
- 右下角悬浮的手动SIM控制器在雨水与协同能效等日常页面隐藏，自动Mock数据仍按统一8秒帧持续运行；有权限的高级分析入口仍然保留模拟调试功能。

## 2. 右上角按钮遮挡的原因和修复

在之前去掉大标题后，`PortSupplyAssuranceView.vue` 的 `main>.tg-biz-head` 实际高度变成 **0px**；按钮本身仍有32px高度，导致下一行 KPI 卡从按钮中部开始绘制，形成视觉遮挡和无法命中。

处理方式：

1. 为协同能效和雨水页面的操作栏保留独立、真实的 **40～44px 布局高度**（`min-height`、`height:auto`、`flex:0 0 auto`）。
2. 保留上下真实间距，使按钮的最下沿始终在 KPI / 运行状态卡上沿之前。
3. 操作栏按实际内容自适应宽度和换行，使用正常文档流，而非通过提高 `z-index` 遮盖下方内容。
4. 不修改全局布局组件、不影响导航栏或其他正在并行开发的页面。

浏览器以 **1600 / 1366 / 390px** 分别验证两页：操作栏高度、按钮实际点击命中（`elementFromPoint`）、卡片前后不重叠、移动端整页无横向溢出。雨水页还验证仅显示本专业模拟事件；业务后端写入次数为0。

## 3. M22-1 运行数据契约

`frontend/src/modules/tanggang/simulation/telemetryContract.ts`

统一 Mock 数据包包含：

- 来源 `feedId`、`sourceMode`、`sequence`、接收时刻、情景ID；
- 每个测点的 `pointId`、`unit`、`value`、采样时刻 `sampleAt`、质量 `quality`；
- `deviceBinding`（Mock严格为null）和 `fieldVerified:false`、`modelOnly:true` 的显式来源限制。

本阶段的数据点范围为：泵状态、压力、流量、电流、降雨量、供水模型初始储量、集水模型初始储量。它们只是统一Mock模型里的观察字段，并不意味着现场已有这些测点或采集设备。

质量判定：

| 质量 | 说明 | 是否允许进入当前Mock分析 |
|---|---|---|
| `synthetic` | 合法、及时且带Mock来源 | 是，仅模拟计算 |
| `missing` | 缺少字段、质量缺测 | 否 |
| `stale` | 超过模型的30秒新鲜度阈值 | 否 |
| `invalid` | 非法/未来时间戳、无效数值、伪造设备绑定或来源、结构不符 | 否 |

**任何Mock包均不得获得正式告警可执行资格**，未来正式现场设备接入必须由经认证的后台接入模块校验设备绑定、单位、质量、时间、权限和工况适用性，本次没有开启该接口。

`store.ts` 现为每帧Mock先创建数据包并检验质量，再更新统一业务数据、运行计算及事件状态；切换人工模拟或停止时清空自动采集包，避免把旧数据误当作新采样。

## 4. M22-1 事件统一读模型、严格分轨

`frontend/src/modules/tanggang/simulation/operationsEventReadModel.ts`

- 对已有 `OperatingCase` 生成 `sim:SIM-CASE-XXXX` 命名空间、`SIMULATION` 事件读模型。
- 对既有正式告警中心的 `AlarmItem` 类型提供只读转换（标识 `alarm:ID`、`PRODUCTION`），要求有效数据库告警ID、设备ID、告警时间和告警等级。
- 同一个只读界面契约可用于以后汇总，但 **两个事件通道分别返回，默认不混排、不跨通道写入**。
- 正式告警数据库存在记录并不证明现场PLC测点已核验，因此不自动设置现场核验通过；Mock事件即使被人工关闭也不能转成生产告警或工单。
- 生产级告警的指派、工单处理、确认和权限仍由既有正式服务和数据库负责；本轮没有新建第二套告警写入服务。
