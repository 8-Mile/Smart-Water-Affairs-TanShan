# 唐港 5190 · M23 运行处置页面、CAD 水循环及运行参数入口

## 本阶段问题与定位

本次根据用户验收意见修复以下实质问题：

1. **主动智能监护**页面原有“合成样本说明”“模拟人工核查演练”等内容占据首屏，规则与操作重复、布局错乱。
2. **模拟处置研判**页面叠加过多表格与 Mock 说明，且浏览器实际存在 `Cannot read properties of undefined (reading 'find')` 的运行错误（依赖旧模拟研判数据）；用户不需要这套模拟研判流程。
3. **水资源循环必须参考实际 CAD 功能**，不能依据单个示意 SVG 自行假设工程水力连通。
4. **供水匹配、泵异常、多机集中用水和降雨风险**需要有统一、明确的入口，允许查看和修改数据，不要求人工按“演练步骤”操作。

## 1. 主动智能监护

`frontend/src/modules/tanggang/business/PortActiveMonitoringView.vue` 已调整为现有浅色磨砂组件体系：

- 顶部状态 + “运行参数”“告警中心”。
- 四项直观指标：泵运行状态、压力、电流、供水缺口。
- 当前模型即时规则发现：参数变为泵故障后立即出现风险证据，不需等待 M21 事件二次确认；注意“即时计算发现”与“连续两帧触发候选事件”是两种不同状态。
- 左侧自动事件闭环，右侧六套系统影响及工艺跳转。
- 复杂规则仅在“监护规则与记录”折叠展开；默认首屏不显示“合成数据说明”大段文字和手动核查步骤。
- Mock 参数不会写正式告警、工单或 PLC；“告警中心”仍是既有正式告警入口。

## 2. 处置方案（原模拟处置研判）

- 右侧对接 M21 统一自动事件，无需先人工创建虚假的模拟分析记录。

本轮**实际打开并解析**工程内的：
- `frontend/public/tanggang/cad/l1-v2_3/V2.3_区域水路关系.csv`
- `frontend/public/tanggang/audit/cad-review/v2/manifest-v2.json`（包括源DWG文件名与SHA256、25条 `designRelationships`、42对象级记录、源图层审查及 `allConnectionsVerified:false`）

- 现有二维图层查看器 `/tanggang/audit/cad-review/index.html` 与V2总控页 `/tanggang/audit/cad-review/v2/index.html`。
- 现有 three.js 三维港区 `/dashboard`。

`frontend/scripts/build_cad_water_network.py` 对原始 V2 manifest 的设计关系及26个 `TG-CAD-*` 对象锚点执行可复现只读抽取，生成 `cadWaterNetwork.generated.json`，`cadWaterNetwork.test.ts` 校验字段与原始数据一一对应。

产品上保留的水资源设计链为：

**堆场/码头雨污水 → 南北集水池 → 含矿污水处理 → 处理达标清水 → 除尘水池 → 中压泵/射雾泵 → 生产用水；洗车台沉淀水返回南池。**

其中南池→北池 / 南池→含矿处理站分别是**备选路径**，不能声称同时启用；处理后水去生态蓄水与生态水回输存在水质、阀位前提；生活污水是独立工艺。原CAD中有起止反向的注释记录，不能逐表格按单向管道画出。

`PortCadWaterNetwork.vue` 将现有真正的CAD总控图、25条设计关系记录、CAD源来源编号、原CAD设施定位、6专业系统快捷入口集中到“水务协同与能效”；支持图层查看与三维港区互访。

**已知CAD边界：** 当前 V2 静态查看器虽然显示 A/B/C 三个专业分图按钮，但当前工程内实际缺少对应分图图片，因此本轮没有制造空白分图或把这几个按钮当成功能入口；新页只链接已存在的总控图/原CAD图层页。CAD 水位高程、池体水位—库容曲线、设备实装管道端点、有效阀门状态未取得经核资料，故没有把模型储量算作CAD真实水位。

## 4. 供水负荷的计算与明确入口

`PortSupplyCoverage.vue` 已集成到“水资源管理 → 水务协同与能效”：

- 用水需求来自**同一批模型终端**及其 `demandM3h` 输入；
- 可分配能力 = 假设供水总能力 - 假设预留能力；
- 按优先级1、2、3给终端分配，逐终端显示“实际分配 / 需求”的条形图；
- 缺口 = 需求 - 已分配；不会把未供水水量视为节水。
- 现有 `supplyPlans` 负责在守住库容安全条件与延迟需求的约束下，提供方案比较；不属于经过泵曲线和管网水力验证的生产控制策略。

## 5. “运行参数”统一入口

`PortOperatingInputs.vue` 已挂载在以下业务页面**右上角**：

- `/port/water/supply`：供水能力与用水终端；
- `/port/operations/monitor`：泵运行状态、压力、电流、流量；
- `/port/operations/decision`：供水方案对应的运行参数；
- `/port/water/rain-risk`：降雨量、历时、集水容量、初始水量、排水流量、汇水面积与径流系数。

抽屉提供“常态作业/多机集中用水/中压泵异常/强降雨入池”四种基础数据组合，能随时修改字段并点击**应用参数**，全部页面重用同一个 `store.applyOperatorInputs` 计算结果。修改时暂停自动Mock帧，以免覆盖人员主动输入；点击**恢复自动更新**后 `store.resumeAuto()` 回到持续自动运行。

**重要布局修复**：联调发现全局旧“SIM自动运行”右下角按钮的层级覆盖了抽屉的“应用参数”底部按钮，造成“看起来能点、实际不能点”。现将旧悬浮入口在运行处置两页隐藏，只保留本页实际可用的“运行参数”；此问题通过浏览器重新点击验证修复。

当前 `applyOperatorInputs` 只生成模型数据、风险线索和内存视图；真实测点接口、生产告警写入和PLC控制均未新增。
