# M24 · 5190 唐港 CAD 水路源证据追溯与六工艺双向联动

## 版本与目标

基于 M23 提供的 CAD V2 水路设计关系视图完成第二轮深挖，目标不是新增“模拟卡片”，而是把原图依据、两端区域、设计设备建议测点和六子系统工艺页面闭合到同一条用户可点击的使用路径。

实际使用路径：

1. **水资源管理 → 水务协同与能效** 打开 CAD 水资源关联；
2. 按“雨污水收集／供水与回用／生活水独立链”过滤已载入的 25 条 V2 设计关系；
3. 选择一条关系，查看起点与终点各自的 **原 CAD 文字锚点／注记**，点击打开原图并聚焦；
4. 通过“查看关联工艺”跳到对应六子系统组态图；
5. 子工艺页新增“关联 CAD 水路”栏，显示同一 V2 关系和“回到水路与 CAD”，返回原关系，保留关系ID；
6. 在“设备与测点准备情况”折叠区域查看该关系两端对应**设计区域**的设备清单、建议数据字段、状态和缺少的绑定关系。

## 一、实际核对过的源资料及边界

真实读取：`frontend/public/tanggang/audit/cad-review/v2/manifest-v2.json`，包含 25 条 `designRelationships`、42 条对象级描述、源DWG名称及来源哈希；`frontend/public/tanggang/cad/l1-v2_3/region-equipment-v2.3.json` 包含设计区域与设备条目；`frontend/public/tanggang/cad/l1-v2_5/systems-v2.5.json` 为六子系统关联区域与设计设备清单。CAD原图已有交互查看器支持 `?focus=09` 等文字点定位。

`V2` manifest 的 `allConnectionsVerified` 是 `false`，因此其设计业务关系 **不等于现场已核实的水力管线拓扑**。 `A01`、`A10`、`D03` 等是原 manifest 的设计关系来源代码，不等于 CAD 原始图元 Handle。只有 `TG-CAD-*` 所对应的真实 `sourceHandle` 才能用于原图追溯。

**重要发现：** 现有设计设备目录的 `sourceCadHandle` 均未绑定，因此并未形成“具体泵—具体CAD图元—采集测点”的已验证一一对应关系。水资源关联视图仅将 CAD 区域/文字与同区域的设计设备目录做**区域级关联**，没有推断每台泵的确切安装坐标。

## 三、代码与页面入口

- `cadWaterTrace.ts`：从 25 条设计关系的节点建立显式追溯表，只标记区域、源CAD文字点、关联子系统及限定范围。
- `PortCadEndpointEvidence.vue`：起点、终点各自展示 CAD 锚点和一键原图定位；展开“设备与测点准备情况”查看设计设备及字段，不显示假实测。
- `PortCadWaterNetwork.vue`：用户从工艺页带 `?cad_relation=L07` 进入时，自动选中并滚动至原关系；不同关系选择写回URL。
- `PortProcessCadLinks.vue` + `PortProcessView.vue`：六个专业工艺页面保持原组态编辑器及功能不变，新增少量跨系统 CAD 关系入口；支持返回原关系。
- `build_cad_water_network.py` → `cadWaterNetwork.generated.json`：从原 CAD V2 manifest 增加抽取 `type`、`isPhysicalEntity`、`verifiedFootprint`，区分文字注记与真实设施。
- `public/tanggang/audit/cad-review/v2/index.html`：检测当前工程缺少 A、B、C 三专业分图图像，置灰无效按钮，增加“打开原CAD图层与定位”可用替代入口；保留真正存在的总控图，绝不加载空白链接。

入口（需要本机 Vite 5190 运行）：
- 水路 `http://localhost:5190/port/water/supply?cad_relation=L07`
- 处理清水回用 `http://localhost:5190/port/water/supply?cad_relation=L12`
- 独立生活污水 `http://localhost:5190/port/water/supply?cad_relation=X01`
- 雨水工艺 `http://localhost:5190/port/process/rain?cad_relation=L07`
- 原CAD图层 `http://localhost:5190/tanggang/audit/cad-review/index.html?focus=09`

## 四、下一阶段真正需要业主验证的字段（目前仅准备，不采集）

以下是现有工程设计设备目录中的原有建议字段，不是模拟数据更换为现场数据所需的全部设备清单，也不作为采购建议：

| 环节 | 设计设备 | 建议数据字段（项目目录原文） | 当前证据 |
|---|---|---|---|
| 北池 | EQ-NPOOL-RADAR 雷达液位计 | 液位、液位报警 | 暂无真实测点 ID/池体一一配准 |
| 南池 | EQ-SPOOL-RADAR 雷达液位计 | 液位、报警 | 暂无每座池体的独立液位点对应 |
| 污水站清水池 | EQ-WWT-CLEAN 清水池及清水泵 | 清水池液位、回用流量 | 尚未验收水质与回用水管线端点 |
| 除尘池 | EQ-DP-TANK 除尘水池 | 液位、可用水量、消防保留水量 | 未取得真实水位—库容曲线及保留水量依据 |
| 除尘池补水 | EQ-DP-METER 进水计量装置 | 累计补水量、进水瞬时流量 | 缺正式计量点与水源识别 |
| 中压泵组 | EQ-P-MID 中压除尘泵组 | 泵运行状态、出口流量、出口压力、故障 | 设计目录有字段但未绑定现场测点 |
| 生态空间 | EQ-ECO-VALVE 双向水管电动阀 | 阀门状态 | 双向启闭条件和实际水质门槛未核实 |

**当前 Mock 供水总储量绝不能直接归属南池、北池或除尘池；系统的供水分配能力不等于水力管网校核后的实际供水能力。**

## 六、仍未完成的工程闭环

这阶段**闭合了界面导航和原图设计依据追溯**，不是实测水量闭环，更不是未经核实的物理管网闭合。要形成真实的水量核算与监护闭环，必须先补：每座池体有效容积和水位关系、处理站清水池与除尘池接管实际接口、各水源独立计量点、用水末端实际计量及作业负荷、设备运行能力和泵曲线、实际阀门状态、生活污水最终实施方案、CAD有效版次及分段连通验收。随后才能建立数据质量和水量平衡核算，而非仅以 CAD 线条推断。
