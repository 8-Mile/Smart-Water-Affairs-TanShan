# 5190｜M5第二批：本地Mock智能助手业务闭环验收

## 定位与明确的数据边界

按照唐港原业务主线开展：生产供水保障 → 主动监护 → 影响分析 → 人工核查 → 复盘。用户允许本地AI使用假数据进行Mock演示。本次使用开发SIM假设数据和确定性的中文意图匹配；**不是已连接大模型，也不是唐港现场实测**。用户上传的资料仍为工程参考依据；不可将假设流量、设备和故障描述成现场记录。

当前开发环境：AI_ENABLED=false、AI_MOCK_ENABLED=true、APP_ENV=dev。本机Mock开关显式启用，默认配置为关闭，且在prod模式强制不生效。旧的真实AI代理代码分支保留。

## 实际入口

- 智能助手主入口：http://localhost:5190/ai/chat
- 我的看板：http://localhost:5190/port/analysis/boards
- 演示设备登记：http://localhost:5190/port/analysis/equipment-drafts
- 大机供水保障：http://localhost:5190/port/water/supply
- 主动智能监护：http://localhost:5190/port/operations/monitor

不增加一级菜单。AI助手顶部保留供水推演、我的看板和演示设备录入入口。继续使用既有聊天布局、Element Plus、业务主题字体与卡片。

## 已落地功能

1. 复用原有 /api/v1/ai/health、/chat、/chat/stream、/confirm、/cancel、/sessions、/sessions/{id} 和 /audit-logs 接口，新增明确的MOCK分支。原前端SSE协议 session/status/tool/pending/token/done 可以完成流式回复和状态反馈。
2. 前端只读取当前Pinia的SIM情景快照传递给Mock聊天（场景编号、runNumber、需水量、模拟分配、缺口、储量、监护规则）；后端仅接收 data_mode=SIM、field_verified=false 的受限字段，拒绝MEASURED、负值或越界数据。无当前情景时给出明确标注的预置MOCK高峰样例（139m³/h需水、105m³/h分配、34m³/h缺口、350m³期末储量），不是当前情景也不是实际测量。
3. 模板意图可完成：模拟供水和监护问答、查询当前用户SIM演示设备、解析新设备指令、生成供水/监护A2UI看板草稿。无法确定设备名称、工艺或编号时提示补全，不自动填入真实现场对象。
4. 新增设备仅先生成操作预览，确认后再次校验eq:create权限、六系统ID、编号冲突和SIM来源，只写独立 tg_demo_equipment；确认后提供演示设备列表入口。绝不写正式 eq_equipment、SCADA、告警、维修工单或CAD映射。
5. 看板仅先生成白名单受控组件预览，确认后在原 tg_a2ui_board 创建服务端草稿并写tg_a2ui_board_revision，返回“我的看板”；后续真正发布仍由原有sys:menu:manage角色控制，不能自动公开发布。
6. 新增 tg_mock_ai_session、tg_mock_ai_message、tg_mock_ai_action 三张Mock专用会话/消息/动作表。动作有唯一ID、独立用户归属、pending/confirmed/cancelled状态，30分钟过期；同一动作无法重复确认，取消后不执行。确认或取消复用已有 ai_audit_log 审计。
7. 会话可恢复并还原已确认/已取消动作及结果入口。危险操作（真实泵阀启停、正式派工、删除设备、PLC控制等）均拒绝；不提供实际控制API。
8. 真实AI服务与Mock明确区分：UI显示“MOCK · 演示”，不展示虚假的模型名称，组件仅用已有Element Plus样式。

## 文件范围

- backend/app/models/tanggang_mock_ai.py：Mock专用三表。
