# 唐港5190：M5一期｜受控设备录入、A2UI保存发布及入口验收

## 业务主线与数据边界

原主线：生产供水保障 → 主动智能监护 → 影响分析 → 人工核查 → 处置复盘。M5作为业务辅助，不替代正式告警、工单或设备管理，不新增一级菜单。

当前唐港系统数据全部来自用户上传资料背景下的研发演示假设、资料推导和待核对工程信息。没有经过现场核实的真实运行数据、SCADA点表、设备位置和供水能力。所有新看板数据均为SIM，并在业务页标明“资料演示”。不会将假设数据写入正式业务台账。

## 完成后入口（需登录5190）

1. 智能助手：http://localhost:5190/ai/chat
2. 我的看板：http://localhost:5190/port/analysis/boards
3. 演示设备录入：http://localhost:5190/port/analysis/equipment-drafts
4. 供水看板发布目标：http://localhost:5190/port/water/supply
5. 监护看板发布目标：http://localhost:5190/port/operations/monitor

“我的看板”位于分析中心子菜单；“演示设备录入”通过AI智能助手页右上角按钮进入（仅具有eq:create的用户显示）。发布后只有允许的用户角色在选定业务页看见该看板；SIM尚未启动时可看到已发布看板标题及空态，不显示伪数值。

## A2UI一期已实现

- 后端独立表 tg_a2ui_board、tg_a2ui_board_revision 持久化布局、状态、创建人、目标页面、角色授权、版本历史。
- 有效接口：GET /tanggang/boards/catalog、GET /mine、POST /、PUT /{id}、GET /{id}、GET /{id}/history、GET /roles、POST /{id}/publish、POST /{id}/revoke、GET /published（以上相对/api/v1/tanggang/boards）。
- 仅允许 metric、terminal-table、monitor-rules、plan-comparison 四类组件，七种SIM指标白名单，每个看板最多8个组件，最多两个明确目标页面。不执行任意Vue/HTML/JS/SQL或LLM返回的可执行代码。
- 前端支持按供水/监护主题匹配已有业务模板、组件调整顺序、编辑、预览、服务器保存、发布、撤回、版本历史。使用已成熟的业务布局、tg-biz-card、Element Plus表格、表单和主题字体，不创造单独的AI卡片视觉风格。
- 发布必须由实际拥有sys:menu:manage权限的用户执行；本机RBAC此权限只授予super_admin。admin/领导角色可被选为可见受众，但没有发布权限。没有修改现有角色授权。
- 发布后的角色隔离由后端校验；撤回后目标页重新读取则不再返回看板。跨浏览器会话即时推送撤回尚未开发，不夸大为实时撤回。
- 使用统一全局SIM情景和供水、监护的确定性结果源。没有真实数据接入，不把模拟指标冒充现场统计。

## 演示设备录入一期已实现

- 独立表 tg_demo_equipment；绝不向eq_equipment、SCADA、正式告警、工单及三维CAD关联写入演示资产。
- 后端 /api/v1/tanggang/demo-equipment/parse 支持明确格式的规则模板解析，缺少工艺/名称/编号时列出缺项；这不是大模型语义识别。
- /api/v1/tanggang/demo-equipment 的GET及POST支持个人SIM演示设备记录列表及人工确认。保存需eq:create权限、实际存在的六系统分类、来源说明、人工确认，拒绝与正式设备表和SIM演示表重复的编号。
- 前端可输入设备描述、核对解析字段、完善资料与假设依据、明确勾选SIM声明、保存后展示独立演示记录；不会假装已经新增正式安装设备。
- 没有真实现场设备资料前不允许通过这条演示操作自动生成正式设备记录或真实三维绑定。
