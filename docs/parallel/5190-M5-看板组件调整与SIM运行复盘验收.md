# 5190 M5：受控看板组件调整、SIM运行复盘和跨业务导航验收

## 范围和事实边界

唐港业务主线仍为生产供水保障 → 主动监护 → 影响分析 → 人工核查 → 运行复盘；延续本机Mock模式，不接真实大模型、不生成正式工单、告警或SCADA历史，不控制泵阀。模型和数值仅为上传资料背景下的SIM演示假设和业务计算，不是唐港现场测量。

原有成熟UI体系不变：沿用Element Plus、tg-biz-card、el-table、el-descriptions、主题字体和路由动画。只在既有分析中心增加一个二级“运行复盘”，不增加一级菜单，也不修改TRAE正在迭代的Three.js港区场景。

## 实际功能与入口

AI智能助手：http://localhost:5190/ai/chat
我的看板：http://localhost:5190/port/analysis/boards
运行复盘：http://localhost:5190/port/analysis/reports
大机供水保障：http://localhost:5190/port/water/supply
主动智能监护：http://localhost:5190/port/operations/monitor

测试指令：生成本轮SIM运行复盘报告；给1号看板添加需求覆盖率指标；给1号看板移除需求覆盖率指标；打开大机供水保障；进入主动监护；打开运行复盘。看板编号应改为用户自己在看板列表中看到的真实ID。

1. 自然语言添加/移除看板白名单组件：必须指定看板ID，或者本人仅有一张看板。支持需水、缺口、储量、覆盖率、监护状态、规则证据、受影响终端和方案比选等已实现组件。拒绝不支持的指标、重复组件、超过8项和删除最后一项。待确认操作包括ID、版本、组件类型、预期布局。确认时重新核对草稿状态、用户权限、版本号及精确单项变更，CAS更新防止覆盖并发修改，记录版本历史与审计。已发布看板不能直接修改，需授权管理员先撤回。结果跳转自动携带目标board编号并选中正确看板。
2. SIM运行复盘：必须先启动统一情景。综合当前轮次的需水/分配/缺口/池容、受影响演示用水点、监护规则、模拟核查结论与待核实事项；先预览，再人工确认保存至新增的独立 tg_mock_ai_report 表。包含SIM、field_verified=false、BROWSER_SIM_SNAPSHOT、未创建正式事件/工单等证据属性。没有启动情景则不允许保存复盘。
3. 复盘页面：原业务风格下的复盘列表、详情、供水与监护证据、人工核查意见、待现场核实事项和JSON导出。后端只允许用户访问自己的报告。正式运行日志、告警和工单都不被写入。
4. 跨业务导航：识别“打开/进入/查看/前往”供水保障、主动监护、我的看板、运行复盘和演示设备录入，通过现有路由白名单生成可点击按钮，不接受任意外部URL或生产操作。会话历史的操作关联到各自回复轮次，恢复后仍可查看确认/取消状态与结果路径。
5. 页面切换偶发空白：沿用已有路由动画，仅在目标页面切换后路由容器仍为空白时提供局部恢复，不重设计全局布局。

后端共38项通过（含原Mock、A2UI、设备隔离和工程对象映射），前端既有39项回归通过，TypeScript检查0错误。隔离浏览器端到端检查：从统一SIM高峰情景读取缺口34m³/h、人工核查意见、1个受影响演示终端和5项待核对条件；复盘预览→确认→保存→打开报告详情；看板v1→v2组件修改→确认→按编号定位看板；自然语言生成内部导航按钮→目标业务页面。1540/390像素布局验证无横向溢出，非WebGL业务前端错误0项。
