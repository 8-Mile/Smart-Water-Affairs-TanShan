# 唐港5190 · M6 模拟处置研判与复核闭环验收

## 范围和原则

延续生产供水保障 → 主动监护 → 处置研判 → 人工选择 → 新一轮SIM复核 → 运行复盘的业务主线。现有供水四方案计算、监护规则和影响分析直接复用，七大一级菜单、成熟卡片、字体和Element Plus体系不变。

全部水量、设备监护、影响终端、方案计算均为依据用户上传资料背景制作的SIM演示假设，不是唐港实测。三个业务角色是可追溯的确定性Mock规则（供水分析、主动监护、处置研判），不是已部署三个真实自主大模型Agent。

## 入口

- 模拟处置研判：http://localhost:5190/port/operations/decision
- 大机供水保障：http://localhost:5190/port/water/supply
- 主动智能监护：http://localhost:5190/port/operations/monitor
- AI智能助手：http://localhost:5190/ai/chat
- 运行复盘：http://localhost:5190/port/analysis/reports

在运行处置现有菜单增加二级“模拟处置研判”，原供水和监护页添加下一步链接。AI助手支持“分析本轮SIM处置方案”及进入研判的固定内链。

## 软件实现

1. frontend/src/modules/tanggang/simulation/mockContext.ts 将同一浏览器情景的供水缺口、分配量、储量、监护规则、受影响终端、人工核查意见和四方案比选，统一转换为一套受限SIM快照。AI助手与研判页面复用这一数据源，不各自制造指标。
2. 后端只读研判接口 POST /api/v1/ai/mock-decisions/analyze 展示三个Mock规则角色的结论、证据、限制条件及四方案。检查方案齐全、ID不重复、基线缺口与同一轮结果匹配、供需/缺口/覆盖率的算术一致性、field_verified=false；混用实测时拒绝。
3. 四方案：维持现状、错峰低优先级用水、优先守住安全储量、假设备用能力增加。展示缺口、顺延量、期末储量与约束。模型约束未通过不能执行；模型未越线也不代表工程可实施。顺延不等于节水；假设备用泵不代表现场存在。
4. 操作人员选择研究方案、填写8字符以上理由，在成熟确认弹窗中批准**仅保存SIM研究记录**。POST /api/v1/ai/mock-decisions 只写独立的tg_mock_ai_decision表及AI审计，不写正式告警、工单、设备、SCADA或PLC。记录明确real_dispatch_executed=false。
5. 只有运行同一情景的**新一轮SIM**（轮次递增且时间快照不同）才能人工复核。POST /api/v1/ai/mock-decisions/{id}/review 比较两轮缺口、监护状态及约束，记录理由；复核后不能再次覆盖。结果始终plan_executed=false，effect_attribution=NOT_DEMONSTRATED。模拟数字改善不能归因于真实执行该方案。
6. GET /api/v1/ai/mock-decisions及/{id}仅查询当前人的研判历史。关闭SIM或刷新浏览器后，已保存的研究选择和复核结果仍可查看；未运行情景不影响历史查询。
7. 随后生成相同情景/对应轮次的SIM复盘，会带上关联研究选择与复核记录，但始终不是现场运行日志。AI聊天的三阶段研判只使用原SSE协议的受控工具轨迹与白名单内链。
8. 当前本机dev配置允许Mock；生产环境及未启用Mock模式时这些API不开放。原有真实AI代理路径保留。

## 推荐演示步骤

1. 在大机供水保障启动统一高峰SIM情景，看现有需求/缺口及四方案计算。
2. 进入主动智能监护查看同轮规则，记录一次人工模拟核查。
3. 进入模拟处置研判，阅读三个Mock规则角色的证据，选一个方案，填写研究依据并确认。
4. 在统一情景控制台重新运行同一情景，调整被允许的模拟参数，回到研判页填写复核意见，比较前后数值。
5. 进入AI助手输入“生成本轮SIM运行复盘报告”，人工确认后在运行复盘页查看关联研判记录。

## 风险与局限

不得将此模拟闭环宣称为现场自动调度、真实智能体自主分析、PHM或设备恢复验收。用户上传资料仍需现场逐项核对后才可决定实际工程方案。后端本机启动检查发现JWT密钥和初始化管理员口令仍为开发默认安全配置；对外部署前必须更换并完成权限、网络和审计安全检查。不得将本机Mock配置直接部署至生产。
