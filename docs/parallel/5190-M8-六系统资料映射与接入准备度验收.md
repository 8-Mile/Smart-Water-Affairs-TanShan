# 唐港5190 M8：六系统资料、工程对象与SCADA接入准备度验收

## 一、业务目标与数据红线

本轮由M7的SIM研判证据链转向真正影响落地的资料完整性与数据接入工程。复用现有设备运维 → 资料与测点核对的菜单和页面，新增六系统准备度矩阵及修订历史，不新增一级菜单、独立Mock资料库或无依据的现场测点。

**当前系统仍为用户上传资料驱动的软件DEMO。** 六系统矩阵只统计已经存在的CAD设计设施清单、工程对象关联、软件设备台账和SCADA点表配置。已建表、已配置、已引用资料不等于现场设备存在、安装完成、PLC联通、数据实测或者管网水力闭环。真正现场核验数量仍然0，不计算接入成功率或准备度虚假百分比。

## 二、入口

- 资料与测点核对（设备运维二级菜单）：http://localhost:5190/port/data/provenance
- SCADA接入配置（超级管理员）：http://localhost:5190/system/scada
- 六套运行监测工艺：原有各自的 /port/process/{systemId} 路由

## 三、本期实现

1. 新增只读接口 GET /api/v1/tanggang/integration-readiness。按六系统聚合已存在的工程对象关系、来源引用、软件设备关联、SCADA测点关联、资料参考测点、推导/演示点、对象关联缺失、归属不一致、设备/测点被删除后的陈旧引用。不会创建新设备、测点或告警，也不请求PLC。
2. 现有页面增加六系统准备度矩阵。点击某系统即联动下方原测点核对表；可以导出CSV核对清单，包含软件资料缺项、设计设施未绑定项、当前设计与业务名称差异。
3. 原测点审核按系统筛选时，过去只筛已填资料归属记录，导致“有工程绑定但尚未资料核对”的点隐藏。本轮修复为取「资料核对归属」和「工程对象绑定候选」的并集；没审核的点只显示“关联候选、待核对”，绝不自动确认归属。
4. 新增测点资料核对修订历史查看入口，复用原有point_review_revision记录。只有已有scada:point:update权限才能修改依据；所有登录用户都可读自身授权页面上的核对历史。
5. 客户端基于已上传CAD清单给出六系统设计设施类别数、未登记工程关系的**具体设施名称**，以及已登记工程对象但缺少软件设备台账关联的设施。设计类别不是实际安装台数，未推导设备数量。
6. 设计CAD来源和业务菜单保留各自原名称；第六系统存在名称口径差异（CAD设计映射“生活污水处理”、当前业务目录“生活污水提升与外送”），在矩阵单系统详情中提示“工艺范围待核”，没有擅自修改原始资料。
7. 仍展示CAD管线图层和各系统原有disclaimer：室内射雾的专属供水管线未核实，参考室外消防管不能当成已证明的专线；中压、雨水、污泥、补水及污水外送等图层和水力连接仍需逐段核查。

## 四、设计设施类别（参考文件v2.5与v2.3）

| 系统 | 资料中可关联的设计设施类别 | 说明 |
|---|---:|---|
| 射雾器除尘 | 3 | 室内射雾设备与供水泵组参考对象；专属管线待核 |
| 中压供水 | 7 | 中压除尘主管可标注，设备接口与分支连通待核 |
| 含矿污水处理 | 16 | 处理场、集水及提升等多个设计设施类别 |
| 雨水收集 | 10 | 雨水线/集水池，不能据此认定全部排水沟方向 |
| 水池供水 | 11 | 中水、自来水、回用候选供水设施 |
| 生活污水提升与外送 | 3 | CAD映射名称与当前业务边界存在差异 |

这些均为设计设施**类别**，不是已安装设备台数、可联机设备数量或者可运行工艺线数量。同一设备可归属多个系统，后端按各系统关联分别统计，但同一系统内部去重。

## 七、下一批真正需要补齐的资料（非默认假设）

1. 六系统分别的正式设备清单/型号/铭牌/安装位置、共用设备与控制边界。
2. 现场SCADA/PLC实际测点表、采集地址、单位、精度、量程、质量位、时间戳、权限与网络拓扑。
3. CAD设计点与竣工点的差异，管道阀门连接、实际介质、流向与集水池位置及数量。
4. 实际业务需求来源（装卸设备作业计划、需水强度、启停、污水进出水量及水质）、池容高程曲线与泵性能曲线。
5. 明确生活污水系统是提升外送还是还包括处理及回用环节，取得业主确认资料。
