# 5190 M9 · 六系统专业工艺节点与业务联动

## 核心决策

本期是Mock驱动的成熟可操作软件DEMO，不把采集设备、现场点表、协议选型或采购作为前置；所有实际采集/设备需求在产品功能和设计稳定后再与业主核实。只依据用户已提供的CAD设计资料建立专业工艺节点及名称；运行指标仅为全局SIM情景假设。保留七大菜单及既有浅色磨砂卡片、字体、Element Plus和路由，不重复造UI框架、不修改TRAE场景。

## 本轮实现

### 六系统工艺工作区 TG-104（第一批）

保持原有 /port/process/:systemId 六条专业业务路由，原普通设备文字清单升级为双栏的工艺设施节点工作区。

- 左侧：依据 systems-v2.5.json 与 region-equipment-v2.3.json 的区域、设计设备类别绘制SCADA样式可选节点；区块是空间分区，不画未经核实的实体管道、流向或阀门联锁。
- 右侧：点击节点立即显示CAD设计设施名称、区域与ID、原文档建议的测点字段、来源、设计数量或章节、现有设备/测点工程关联；有权限才能进入原对象关联弹窗，已有资产才显示原设备详情跳转。
- 可通过 /port/process/middle?facility=EQ-P-MID 进入中压泵组设计节点；刷新和路由切换根据有效设施ID恢复；未知节点自动回退到本系统首个设计设施，不拼造设备。
- 同一设备设计类别可在多个系统被引用，不复制台账，不暗示两系统间真实水力连通。缺失或区域不匹配的设计记录明确报错，不自动创造新设施。
- 复用唯一全局SIM状态：middle只展示全系统需水/分配/缺口；pool只展示统一模拟水池的整体期末储量；rain只展示独立模拟集水单元的降雨/溢流；其余系统没有可靠单设施模拟值时明确不展示。所有这些数字都不会写到某台泵、仪表、集水池节点。
- 生产供水页及主动监护页增加一键到中压泵组设计节点的业务跳转；仍然能直接跳原告警中心、正式维修工单与模拟研判流程，不制造假告警。
- 源设计domestic写“生活污水处理”，业务口径继续显示“生活污水提升与外送”。保留设计设施和原材料免责说明，不把设计中一体化污水处理设施直接认定为实际运行工艺。

### 测试及边界

- 新增纯函数 processSchematic.ts 和组件 PortProcessSchematic.vue，用于统一处理六组区域/设施选择，不开发通用组态编辑器。
- Vitest验证实际CAD清单6系统完整性，节点类别数分别为3/7/16/10/11/3，区域一致、缺失设计项不制造、室内射雾不偷用消防管作专线。
- Browser Chromium隔离业务API，逐个打开六路由、点击节点、检查地址深链、模拟关联资产和测点、启动高峰SIM联动、390像素下无横向溢出，正式API不写入。
- 当前仅为专业设施节点底座，不宣称完成可验证的SCADA管线真实组态；后续应继续按用户成熟设计图补充六系统专业图形/节点素材和Mock运行状态，并保持全局SIM一致。
- 三维场景、模型、材质、CAD源文件及TRAE迁移目录均不在本提交范围。
