# 唐港5190｜TG-205 供水与监护关联分析（SIM软件层）验收

## 一、严格遵守的业务主线与数据前提

既定主线：生产供水保障 → 主动智能监护 → 影响分析 → 人工核查 → 处置复盘。本轮**不新增一级菜单、不增加重复事件中心、不做PLC自动控制**，优先复用5190成熟组件和既有模拟数据。

所有工程资料均来自用户上传材料；运行参数、用水终端、供水能力、压力、电流、水池储量和推演事件都属于演示假设或计算推导。软件运行正常并不等于唐港现场系统已接入、设备故障已经诊断或场景经过工程验收。

### 计算及关联逻辑

- 新增纯函数 impactAnalysis.ts，统一以当前 effectiveScenario、calculateScenario、assessSimMonitor 和 compareSupplyPlans 为输入。来源、情景ID及规则一致性校验失败时拒绝合并。
- 从供水分配结果中只列出有 shortageM3h > 0 的 DEMO 终端，不将港口其他设施自动推断为受影响对象。展示需求、已分配量和缺口。
- 监护展示已命中及数据不足的规则。规则与供水缺口同一情景发生，属于演示相关性，**不证明泵故障是缺水根因**。
- 核对事项按条件生成：点表质量、作业负荷、泵运行工况、库容水位、管网水质与操作权限。均显示待现场核对，绝不自动通过。
- 四供水方案保留假设安全储量的模型限制。模型计算结果不等于可执行生产调度方案。
- SIM报告保留 stage DOCUMENT_BASED_DEMO、dataMode SIM、fieldVerified false、inferenceType RULE_EXPLANATION_NOT_AI_DIAGNOSIS。
- 本轮**没有直接接入AI模型**，这些文字解释由确定性业务规则产生，不能对外宣传为AI已完成故障根因分析。
- 导出JSON只是用户浏览器下载，不向正式告警、维修工单、SCADA历史或运维档案表写入。
