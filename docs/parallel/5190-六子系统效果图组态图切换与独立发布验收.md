# 唐港5190 · 六系统效果图/组态图切换与独立发布（2026-11-23）

## 需求与结果

1. **去掉子系统页面顶部标题和“返回港区”按钮**：直接以模式切换栏开头。全站顶部导航和左侧菜单保留。
2. **解释“Mock演练”**：仅为基于CAD设计字段的模拟工况，数据和阈值均不代表业主现场值。UI核心词改为“模拟工况”，保留Mock来源说明；不会操作PLC或生成正式告警、工单。
3. **编辑完找不到发布按钮**：六套工艺统一使用原射雾SCADA图元编辑器。编辑时顶栏、底部都有“保存并发布”；有修改则先调用服务端保存草稿，再由管理员确认发布。已保存、未发布的草稿在退出编辑后显示“发布已存草稿”。
4. **效果图/组态图切换**：每个子系统均可直接切换，两个视图使用相同CAD设备ID，点击后进入现有右侧设备详情。编辑时禁用切换以保护未保存内容；从组态退出后仍可切换。

## 六系统独立版本

| 系统 | systemId | CAD设施数 | 组态能力 |
| --- | --- | ---: | --- |
| 射雾器除尘 | fog | 3（默认6个视觉图元） | 沿用旧工程模板 + 服务端草稿/发布/版本恢复 |
| 中压供水 | middle | 7 | CAD分区生成默认可编辑模板，独立服务端版本 |
| 含矿污水处理 | mineral | 16 | 同上 |
| 雨水收集 | rain | 10 | 同上 |
| 水池供水 | pool | 11 | 同上 |
| 生活污水提升与外送 | domestic | 3 | 同上 |

专业工艺的已确认“设施类别”来自现有上传CAD对应资料，模板中的坐标和尺寸仅供界面排版。**除射雾已有设计示意线外，其余五系统默认不创造任何水力连接。** 人工添加的连接只能为 `illustrative`（未经校核），不能冒充实测水网。

接口独立：`/api/v1/tanggang/process-diagrams/{systemId}` 及 `/draft`、`/publish`、`/history`、`/restore`。六系统各有 `draft_revision` 和 `published_version`。旧 `fog` 接口、历史版本和交互测试保持兼容。

权限与限制：原工程 `eq:update` 可编辑；`sys:menu:manage` 可发布/恢复历史，延续严格的发布权限。权限不足时“保存并发布”显示但禁用并提示管理员授权。发布**仅更新软件运行组态与CAD设计设施绑定**，无设备台账新增、真实测点、正式告警/工单或PLC写入。

后端独立部署：CAD允许绑定的设施与建议字段从 `systems-v2.5.json`、`region-equipment-v2.3.json` 生成固定的 `backend/app/resources/tanggang_process_facilities.json`。后端不再在运行时依赖前端项目源码目录。

## 效果图的证据边界

效果图当前为根据CAD设计设施/分区及项目已有图元PNG生成的**工程概念效果示意**，用于看设施组成与点击关系；它**不是**此前上传的高保真效果图片，不代表工程实际空间坐标、设备台数或真实水力连通。旧 `spray-reference.png` 截图包含与当前CAD签认数量不一致的演示设备与读数，故不直接拿它冒充正式效果图。后续需要逐张导入经确认的六系统独立效果图资产才能达到历史效果稿的1:1复原。
