# 5190统一情景推演：一处选情景，多页面联动

## 需求决策
用户不希望在“供水保障”“雨水管理”“智能监护”等专业页单独填写用水量、模拟降雨或泵组状态，要求统一入口选择情景，所有页面按同一份结果即时更新。此需求已按第一阶段真实实现。

## 已实现入口与路由
- 用户登录后，浏览器右下角出现全局按钮“情景推演”。它在Three.js首页和5175业务页面均可打开。
- 统一控制台 / src/modules/tanggang/simulation/ScenarioConsole.vue：常态作业、多机集中用水、中压泵异常、强降雨入池四个预置情景。只能在此处启动/切换/结束。
- 水资源管理 /port/water/supply：大机供水保障，按共享情景展示用水需求、分配能力、供水缺口、终端分配和储量预测。
- 运行处置 /port/operations/monitor：主动智能监护，展示同一情景的压力/电流/运行状态和规则化线索，提供进入原告警中心入口。
- 水资源管理 /port/water/rain-risk：雨水调蓄风险，显示同一情景下的演示径流、库容和溢流。
- 运行监测的六工艺详情：中压供水、水池供水、雨水收集会显示情景影响的只读摘要，其他工艺明确提示当前没有核实的物理管线关联。
- 各专业页面不允许直接修改模拟用水量、雨量或阈值；可点击“打开统一推演控制台”唤起相同的全局入口。

## 数据架构
- src/modules/tanggang/simulation/engine.ts：纯函数假设模型；优先级分配模型、单池恒流储量公式、简化监护规则、雨量-径流-库容公式与SIM事件。
- src/modules/tanggang/simulation/store.ts：Pinia唯一共享状态，当前仅保存在应用内存。切换路由保持当前情景；刷新或退出登录撤销，不写入数据库、localStorage、生产告警、工单或PLC。
- 每轮场景按SCENARIOS静态假设输入，禁止标识为MEASURED或REAL。演示编号DEMO-MA/MB/MC/MD不是唐港现场大机设备ID。
- 推演日志与审计仅用于浏览器的当前运行实例，尚未建立持久化仿真任务编号或审批记录。

## 核心算例（全部为演示假设）
- 常态：需求56、可用100 m³/h，缺口0。
- 多机高峰：需求139、可用105 m³/h，缺口34；12小时演示末储量350m³；预计11小时触及400m³假设安全储量；电流125A形成“压力未越限但电流偏高”线索。
- 泵异常：需求94、可用45 m³/h，缺口49；演示泵状态异常与低压线索。
- 强降雨：80mm、18,000m²假设汇水面积、径流系数0.72，对单池推演径流1036.8m³，假设溢流406.8m³。不是实际港区全部雨水池的结果。

## TRAE三维引擎联动接口（待对接，非本轮验收）
当前全局控制台已在首页显示运行状态；三维场景本身尚未订阅状态自动高亮。
由TRAE在其持有的scene目录中订阅Pinia状态，或侦听以下只读事件：

window.addEventListener('tanggang:scenario-visual', listener)

开始事件detail：
{scenarioId:'peak'|'baseline'|'pump-fault'|'storm',runNumber:number,dataMode:'SIM',simulationOnly:true}

退出事件detail：
{scenarioId:null,runNumber:number,dataMode:'MEASURED_OR_UNAVAILABLE',simulationOnly:false}

建议视觉关系：peak→中压供水+水池供水，pump-fault→中压供水，storm→雨水收集，baseline→综合状态；仍需按CAD对象映射校核。
一切可视效果都只能改变SIM图层、标签与颜色，退出后恢复原始实测/未接入表现。不得创建虚构水路连接、伪造泵设备状态，更不得据事件执行控制命令。

注意：用户当前明确要求我与TRAE并行，我不修改任何Three.js scene文件，防止冲突。

  启动多机高峰 → 供水页139/105/34m³/h；
