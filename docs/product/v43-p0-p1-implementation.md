# 唐港智慧水务 V4.3｜P0–P1 业务闭环实施与验收说明

基准文件：2026-11-17 最新《唐山港京唐港区51、52号泊位智慧水务系统总体技术方案》34页。
基线代码：V4.2 commit \`da904ce\`。新分支：\`feat/v43-p0p1-business-closure\`。
原则：复用现有六工艺、告警/设备/工单、雨污水与三水源模型、岗位权限、AI/A2UI/报表/档案，不另起演示站点。保留未提交射雾开发文件。

## 一、P0：直接补齐三条高价值业务闭环

### P0-1 设备故障独立恢复复核

入口：\`/operations/events\` → 具体告警 → 原工单办理（优先在事件内抽屉）→ 验收归档 → 原告警“独立核查关闭”。
- 值班人员确认告警；工单按原状态流转：草稿→待派单→维修中→待验收→归档。
- 管理岗位只能在原告警已确认、原工单有引用且已验收后进入恢复复核。
- 新增必填：同一指标、处理前值、处理后值、单位、现场复测/证据编号、人工判断和理由；选择“未恢复”时关闭按钮禁用。
- **命令层再次校验上述结构化证据**，杜绝绕过UI只写一句“已处理”就关闭告警。
- 记录到原告警 \`recoveryReview\` 和既有审计 \`alarm:close\`，归档后仍可查，不改写原始监测曲线或健康分。
- 只记录 USER_ENTRY 人工判断；不会凭模拟值证明现场设备物理恢复。

### P0-2 强降雨污染水调蓄 / 处理 / 回用方案

入口：\`/water/balance\`。
- 同页比较默认、当前、保守（水质/路径不可用）情景，支持逐项修改计算条件。
- 生成独立 \`WBC-*\` 草稿，冻结原始参数、输出、输入依据及时间；更改表单不覆盖旧草稿。
- 状态机：模拟草稿→提交研判→管理岗位拟采纳/不采纳→水务岗位跟踪复算→管理岗位复盘归档。
- 人员权限、生效来源、方案负责人、研判依据、复测依据与复盘结论独立记录；不采纳也留痕。
- 计算含矿污水池容量超限与供水缺口，不等于合法排放或允许工艺调度；相关假设仍待施工图、流量计、V-H曲线、水质与污水厂实测能力支持。

### P0-3 应急协同

入口：\`/operations/emergency\`，或事件中心“发起应急协同（草稿）”。
- 三套预设模板：关键供水中断、极端降雨积水风险、重要设备故障。
- 独立 \`EMG-*\` 草稿，关联原告警和设备，要求管理者人工填写已批准预案编号、指挥负责人、候选资源及可用性说明、各岗位联系人。
- 模拟启动后生成带时限、责任岗位的任务；岗位反馈必须提供措施与证据编号。
- 未完成任务超过模拟时限：管理岗位**手动**检查并升级转派、记录变更；绝不声称已发送短信或电话。
- 全部任务反馈后才允许提交复盘、记录审核依据并归档；历史处理时间线可回看。
- 应急归档与原告警关闭独立；资源、预案与真实联络仍需现场核实，自动调度/工控不实现。

## 二、P1：实际操作与数据下钻

### P1-1 水源与计量点、用途追溯

入口：首页绿能三类数据、\`/water/overview\` 的四张水量卡、\`/water/ledger\`。
- KPI 分别携带 \`source\` 转到对应分类账本，不再要求人工找多个筛选。
- 账本逐行选择：原编号、统计月、来源、流向、金额以外的水量、处理环节、口径说明。
- 对未知计量点及最终终端显示“缺数/待核”，绝不将雨水入池视为循环水流量。
- 水务/运维岗位可以提交计量点与用途的资料登记，管理岗位内部审核；\`fieldVerified=false\` 保证内部资料审核不冒充物理管网实测确认。
- 可进一步进入工程核查底账。

### P1-2 岗位工作台

入口：\`/operations/role-workspace\`，运行中心新增侧边导航，首页保留原有“岗位待办”并增加“我的工作台”。
- 管理者：闭环审批、待验收、应急督办、水资源方案复核与报表。
- 值班员：事件、巡检、工单、交接班、应急草稿。
- 运维：维修工单、健康评分、设备技术档案、工程岗位应急反馈。
- 水务/环保：动态平衡、三水源账本、雨污水处理、AI图表、应急水质/消纳检查。
- 系统管理员：完整流程、权限、配置与审计。
- 只读角色：仅入口和只读业务视图，不显示办理权限。
- 使用既有 store 业务状态，不另外生成“我的待办”副本或第二套工单。

### P1-3 AI问数→A2UI图表→版本看板→报告审核

入口：在首页“问AI”询问中水等水量→“基于账本生成受控A2UI图表并保存”，或 \`/data/ai-workspace?mode=water\`。
- 本地 \`waterSurface.ts\` 将月度分类账本生成白名单 A2UI 趋势图、月度表格、KPI与缺数提示；支持柱状、折线切换。
- 含矿污水处理量对比在明确要求时单列处理过程量，不能被当成合格回用。
- “今天/近30天”问数发现无逐日数据时保留警示，**不能将月账本绘制成每日曲线**。
- 保存看板复用现有个人看板模型、权限、版本与历史；刷新后可恢复同一 dashboard ID。
- 新增报告草稿从**已保存的**水资源 A2UI 生成 \`WAR-*\`，引用原 dashboard ID+版本、月度来源、不同水流口径及缺测限制。
- \`/data/reports?analysisId=WAR-...\` 可查审、导出 Markdown；管理岗位审核说明形成历史，不自动生成官方节水绩效或合法排放结论。

## 三、明确保留的工程约束

本版是可连续操作的**本地软件 DEMO**，不是已完成的生产工程部署：
- 设备实时遥测、PLC/SCADA 联锁与远程控制、视频AI、气象预报、工控安全隔离、实际自动预警和人员通知均没有生产系统接入。
- 大机真实用水端、管路拓扑、末端压力、供水设备能力、药剂与电耗测点、处理站与回用管网连通关系尚待现场勘察。
- 日级真实计量、洗车等循环水回路流量/补水计量、水质化验与真实节水评价不可拿月度演示账本替代。
- 所有“已采纳”“已验收”“已归档”只代表**DEMO本地业务状态和人工录入依据**。不等于现场调度批准或实际设备恢复。
- localStorage 本地数据无法代替正式后台数据库、多人并发、审计签名和灾备；接生产前需后端持久化与服务端权限校验。

## 四、验收用例与下一阶段

单元测试覆盖：P0 三大流程状态机、非法转移/权限、输入依据、超时升级和多角色反馈；P1 计量资料映射、A2UI 白名单校验、报告看板版本与审核权限。
浏览器测试覆盖：P0 真实点击从草稿→审批/验收→跟踪→复盘、跨页恢复；P1 KPI 下钻→选行→登记/审核、问数→图表→保存→报告复核；390px/768px/1366px 响应式。

完成本轮业务实现和回归后，可**开始视觉页面设计**，顺序：岗位工作台→事件/工单→动态平衡→应急协同→水资源账本→AI A2UI/报表。
设计稿须以新业务数据结构为基准，不应通过删减复杂业务按钮换取空白卡片，六套工艺、SCADA、档案与 AI 快捷入口继续保留。
