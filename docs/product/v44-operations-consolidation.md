## 决策：不是继续堆页面，而是删除重复入口

### 取消两个独立页面
1. **岗位工作台**：不另设独立页面。原先的六种角色仍使用同一套权限和岗位队列计算；首页协同处置区域显示当前角色和**常规可办理事项**数量，点击进入统一事件中心，展开原有岗位待办及快捷入口。不会额外存储第二套岗位任务或再造个人中心。
2. **应急协同**：取消独立侧栏入口和独立路由页面，作为统一事件中心“协同处置”工作区内的任务办理视图。事件详情的“升级应急处置”直接切换内部视图，不离开当前事件上下文。仍允许从事件队列上的“查看应急任务”检查跨事件任务。

### 只保留一个明确的运行入口
- 侧栏原“运行中心”（三级展开）收敛为一级直接链接 **运行处置** → `/operations/events`。
- 事件中心保留四个工作区：**全部事件 / 值守巡查 / 生产告警 / 协同处置**。协同处置内部在“跨系统关联核查”和“应急任务”之间切换，而不是再开第五个顶层栏目。
- 事件详情将常用按钮保留在前：原事件、原位办理工单、快速设备详情、升级应急；完整工单、完整设备工作台和跨系统关联核查收纳到“更多操作”。
- 应急内部依然保留原 EMG 编号、来源事件、预案核验、指挥责任、资源条件、时限、岗位反馈、人工升级和复盘状态；**未删除任何模型字段或操作历史**。
- 为防止应急业务断链，对生产告警保存 `alarm:<ID>`，智能巡查保存 `duty:<ID>` 原始引用（`sourceEventRef`）。同一来源有未归档任务时返回已有记录，不重复开单。旧 localStorage 记录字段兼容。

## 不合并的专业业务（经产品判断）

`/water/machine-supply`、`/water/balance`、`/water/ledger` 的业务对象分别是 **大机供水末端/供水能力**、**水量守恒/方案比选**、**计量来源与用途核算**，不是同一张表的不同标签。直接合并会加长页面并模糊专业口径。因此本轮保留它们各自的独立工作区及现有的相互带参跳转；水资源导航本身已收敛，不再新增业务卡片。

六套工艺、SCADA、设备档案、健康评分、工单、雨污水处理、AI/A2UI 看板和报表仍保留；不修改用户尚未提交的射雾工艺代码、设计截图或 `.trae`。

## 用户操作闭环验收要点

- 首页“岗位待办” → 运行处置 → 当前角色可办理事项（不与应急待办混算）。
- 告警事件 → 原位关联工单 / 设备核查 → 需要时升级应急 → 预案、任务、证据、复盘 → 返回**同一原始事件**，并保持告警关闭与应急归档的独立状态。
- 智能巡查事件同样可升级应急，保留原 `duty:` 编号，不伪造生产告警。
- 同一未完成来源事件不重复生成应急任务。
- 旧地址及历史浏览器模拟记录继续可用，避免用户收藏链接失效。
- 1366px / 390px 等屏幕上的运行处置不发生横向溢出。

本轮只作信息架构与使用流程减法，不启动新视觉稿。后续若需要重新设计 UI，应以统一事件中心、简化后的业务入口为准，而不是恢复多个互不相干的功能页面。

## 开发限制

这仍是本地 DEMO：应急预案、人员权限、任务反馈、工单和证据由本地模拟数据与浏览器存储组成；没有生产系统工控接入或真实通知。保留 V4.3 的“工单归档不等于告警自动恢复”规则。
