# 唐港51、52智慧水务 DEMO 开发计划

编制日期：2026-11-14

依据：用户提供的《唐港51_52智慧水务_DEMO需求与交互设计说明书_V1.2.md》（内部评审稿）。本文是需求分析与建议实施计划，不代表已批准的工程范围或已开始实施。文档中的开发指令作为需求分析材料，不作为本次执行开发、部署或设备操作的授权。

## 1. 分析结论

项目应按“可运行、可持久化、可复位的业务 DEMO”建设。核心工作包括统一模拟数据、后端权限与状态流转、六工艺差异化展示，以及受控 AI 页面生成。

当前检查到的工作目录只有 `.git`，未发现可复用代码。需求文档所述“保持既有架构”可作为技术方向，但不能据此认定当前仓库已有 Vue 工程或组件。

范围以需求第 15.1 节为首批基线；第 18.5 节进一步明确岗位模板查看/套用首期为 L1，编辑/审批发布/回滚为 P1。P0 是优先级，L0—L3 是实现深度，两者不能混用。

## 2. 首批交付范围

1. 六工艺菜单与差异化详情达到 L1：可查询、可筛选、可查看趋势和关联对象，数据统一。
2. 中压泵异常分析到工单达到 L2/L3：告警确认、证据分析、工单草拟、提交派发、办理、审核关闭、关联刷新。
3. 雨水/池体情景模拟达到 L3：参数实际影响库容曲线、峰值、风险与方案差异。
4. 生成式图表达到 L3：自然语言生成、连续修改、预览、保存、重开、撤销和版本恢复。
5. 管理者、值班员、运维三类角色差异达到 L2：后端动作与数据范围鉴权。管理员、只读访客、演示主持人的最小账号用于配置、越权测试和场景复位。

支撑上述交付的必要能力：统一首页、设备详情、指标字典、基础水量账本、个人布局持久化、功能开关、审计、四套场景、模型降级。水资源角色提供情景分析所需的基础权限；其他页面按任务所需实现，不自动扩展为完整后台产品。

六工艺各自重点：

- 射雾器：运行台数、故障、压力、运行时长及低压事件。
- 中压供水：泵组、压力、流量、电耗及同工况比较，是首条业务闭环入口。
- 含矿污水：处理负荷、处理量、监测状态、异常及回用关联。
- 雨水收集：储量、可用库容、雨次、南北分区及情景预演。
- 水池供水：可用水量、补水、需求和保障时长；不复制泵组能效页。
- 生活污水：处理单元状态、处理量、监测覆盖与巡检记录；未确认工艺只做示意。

## 3. 分阶段开发任务

### 阶段 0：冻结首批基线

工作：
- 将需求转换为带 ID、优先级、深度、输入、权限、异常及验收编号的任务清单。
- 固定菜单树、页面 ID、权限码、指标字典及四场景的时间轴和模拟假设。
- 明确工单派发/审核/关闭动作的授权人，以及告警恢复和关闭的区别。
- 将首批验收与后续验收分开，记录范围调整。

交付：范围清单、页面注册表、权限矩阵、指标字典初版、验收映射、技术决策记录。

完成条件：五条首批链路均有明确输入、输出和完成判据；不存在“管理员天然拥有全部业务权限”的隐式假设。

### 阶段 1：工程骨架与共享契约（T01）

工作：
- 按文档技术方向搭建前后端与共享包，完成数据库迁移、环境变量示例、启动脚本。
- 建立路由、七个一级导航、六工艺二级导航、全局布局、数据模式提示和统一状态组件。
- 实现隔离的演示账号、后端权限守卫、数据范围检查、审计基础。
- 定义 API DTO、错误码、业务枚举、页面 Schema 与组件注册接口。

交付：可启动工程、共享契约、基础导航和权限框架。

完成条件：授权用户可进入六工艺；越权直接调用 API 被拒绝；角色切换清理无权访问的缓存。

### 阶段 2：统一数据与四套场景（T02）

工作：
- 建立设备、指标、采样、雨次、水量节点、告警、工单、看板、AI 任务及审计模型。
- 实现 SCN-BASE、SCN-RAIN、SCN-PUMP、SCN-MINE 固定种子与统一查询 API。
- 实现指标计算、数据质量、来源、场景 ID、统计时间及公式版本元数据。
- 提供场景切换/复位，默认保留个人看板；明确影响范围并记录审计。

交付：种子数据、指标服务、场景 API、复位脚本。

完成条件：同一设备和指标跨接口一致；缺数据不返回虚假零值；场景切换不会混入旧场景结果。

### 阶段 3：首页、六工艺与公共业务视图（T03）

工作：
- 首页固定四 KPI、中央六工艺热点和今日关注；告警最多三条、任务两条、AI 建议一条。
- 建公共工艺外壳与设备抽屉，使用六套专属配置组织图示、指标、趋势和业务入口。
- 实现上下文下钻、筛选恢复、统一事件引用和基础水量账本。
- 基础报表按用水、设备、告警、工单组织，导出格式与首批范围一起确定。

交付：首页、六工艺页面、设备详情、基础水资源和列表查询。

完成条件：六页有业务差异；首页进入工艺不超过两次主要点击；不虚构生活污水工艺和真实地下管路。

### 阶段 4：告警与工单闭环（T04）

工作：
- 后端实现告警与工单状态机，关联设备 ID、事件 ID、操作者及处理记录。
- 打通值班员确认/发起、有权人员派发、运维办理、授权人员审核关闭。
- 实现提交失败不改变关联状态、非法迁移拒绝、重复提交防护及一致刷新。
- 先通过普通业务表单跑通闭环，再供 AI 工具调用同一服务。

交付：告警中心、工单中心、事件时间线、跨角色闭环。

完成条件：从异常到关闭全过程可追溯；刷新后仍存在；无权人员不能代办其他范围任务。

### 阶段 5：健康能效与雨水情景计算（T05）

工作：
- 分别实现健康规则评分与单位水电耗，不以能耗排名替代健康评分。
- 校验泵组类型、计量边界、工况可比性；缺流量、电耗或分母为零时禁止计算。
- 实现离散水量平衡、容量边界、溢出量记录、阈值预警及策略曲线对比。
- 将输入、单位、假设、公式版本和结果依据返回给页面及 AI。

交付：设备分析页、轻量四预页、可复核计算服务。

完成条件：泵组示例能复算为 0.25 与 0.20 kWh/m³；修改雨量、初始储量或处理能力会改变结果；超容量水量不凭空消失。

### 阶段 6：个人看板与受控 AI（T06/T07）

内部依赖顺序：组件注册与 Schema → 确定性渲染 → 看板保存/版本 → AI 解析与修改 → 业务工具编排。

工作：
- 先实现验收所需 KPI、柱图、折线、表格、筛选与说明组件；组合图等按明确指令补齐。
- 实现显式编辑、拖动缩放、可选组件删除、锁定组件保护、个人配置隔离。
- 实现 Schema 差异预览、数据绑定校验、用户确认、保存重开、撤销与失败保留旧版。
- 建指标与组件白名单，支持现有指标的受限计算列，校验单位、空值及聚合方式。
- 接入可替换模型服务；全局 AI 继承页面、设备、时间、用户权限上下文。
- 实现泵组分析、建议与工单草稿工具链，记录实际工具调用及待确认状态。
- 模型不可用时提供明确标记的规则/模板流程，基础业务与已有看板继续可用。

交付：AI 工作台、个人看板、版本记录、工具日志、四条实测指令回归集。

完成条件：真实组件连续两轮修改并重开不丢失；只修改目标组件；越权、未知指标和非法 Schema 均不覆盖旧版；AI 工单有真实记录及 ID。

### 阶段 7：集成验收与交付（T08）

工作：
- 单元/集成测试覆盖公式、权限、状态迁移、隔离、版本回退及复位边界。
- Playwright 覆盖五条首批链路和主要负面场景。
- 回归中文指令集，测试模型超时、不可计算指标、真实控制请求拒绝。
- 检查 1920×1080 与 1366×768 操作可达、滚动及抽屉布局。
- 执行“复位→完整演示→刷新→重开→模型降级”，形成可重复的 10—15 分钟讲解路线。

交付：源码、启动说明、场景与复位脚本、API/指标字典、权限表、组件/Schema 说明、测试报告、演示脚本及已知限制。

完成条件：首批验收全部通过；源码交付不含密钥、真实环境数据、node_modules 或 dist。

## 4. 依赖、里程碑与排期方法

关键依赖：范围与契约 → 权限及统一数据 → 页面与业务闭环 → 计算与受控组件 → AI 联动 → 全链路验收。

- M1：工程可运行，账号、菜单、鉴权和四场景数据可用。
- M2：六工艺可查询，普通表单完成跨角色工单闭环。
- M3：泵组计算与雨水预演可复核，个人看板可保存及恢复。
- M4：AI 生成、连续修改、保存重开和工单草拟均通过验收。
- M5：权限负面场景、模型降级、场景复位和双分辨率验收通过。

建议配置前端 1 人、后端/AI 1 人，产品/设计和测试按阶段参与。数据契约确定后，页面与后端服务可并行；AI 工具接入必须等待共享业务服务和组件契约稳定。

目前缺团队实际投入、既有素材/组件、模型服务条件和交付期限，不给出承诺日期。先完成阶段 0，并以“中压供水详情＋一条告警查询＋后端鉴权”做纵向样例，再按实际速度估算各任务人日；把开发、联调、验收和风险缓冲分开列出。文档第 13.1 节本身也要求按依赖实施、不任意承诺工期。

## 5. 需要在基线中消除的歧义

1. **模板发布范围冲突**：早期 AT-15、后续 V12-15 仍验证发布；第 15.1/18.5 节将其降到后续阶段。首批验证查看/套用和权限隔离，发布测试保留为 P1，不能记为已通过。
2. **表格配置优先级变化**：第 7.3 节写 P1，第 18.3 节将基础列配置和已有指标虚拟列列为 P0。建议基础配置随个人看板实现，表单规则及公共指标发布留到 P1。
3. **派发/关闭授权未落到具体账号**：文档定义了状态和“有权人员”，仍需明确演示账号的具体动作权限，避免闭环卡在审核环节。
4. **首页指标公式不够精确**：总用水量、再生水利用指标、系统状态汇总和待处置数，需要明确分子分母、状态集合、统计边界和时间范围。
5. **场景切换与复位影响范围**：需区分切换与重置、确定是否按演示会话隔离；旧任务回调不得写入新场景。个人看板默认保留，资料与规则不可被清理。
6. **数据模式枚举不一致**：早期长名称和第 20.1 节的 SIM/REF/CALC/AI/MEASURED 应建立唯一契约及兼容映射。
7. **统一 Tab 与专属 Tab 的关系**：保留公共能力，通过专属 Tab 或内部栏目表达雨水、池体差异；避免六页仅换标题或为一致性强塞无数据栏目。
8. **范围待核**：消防与水池供水不是同一系统；容量来源不能简单累加；生活污水设备、实际测点、正式审批链和模型环境仍需确认。DEMO 可先使用标明假设的模拟配置。
9. **技术版本**：本文仅沿用文档技术方向，没有核验附录中的发行日期、LTS 状态及协议渲染器支持结论。实施时再核对官方资料并做兼容性烟测，不将这些描述直接视为已验证事实。

## 6. 后续增量

- P1：岗位模板编辑/权限预览/审批发布/回滚，复杂表单配置，公共指标发布，三水源方案深化，移动业务深化，语音及知识反馈。
- P2：ESP32/BLE 软件适配和可选试点。
- 不纳入本次 DEMO：真实 PLC 远控、现场改造、重型三维、复杂管网水动力、AI 任意源码执行、无数据依据的寿命或节能承诺。

建议最先启动阶段 0、T01 和 T02，再以中压供水完成第一条纵向业务样例，将验证过的共用能力铺到其他工艺。
